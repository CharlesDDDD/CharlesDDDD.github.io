Reading a Pretraining Run

Chunyuan Deng · September 2026

Contents
1. First screen 2. Metric index 3. Loss 4. Gradients and spikes 5. System health 6. Tensor probes 7. Expert balance 8. Residual paths 9. Modality paths 10. Evaluation 11. Common mistakes 12. Keeping probes cheap

A probe is a measurement attached to a training run. A large run emits tens of thousands of them, and the hard part is knowing which ten to watch. So every metric here carries a priority as well as a definition, an aggregation rule, and a default cadence.

LevelMeaningTypical cadence
P0 Alert. Wired to a pager. Roughly ten metrics; if one moves, the run stops or someone wakes up. Every step
P1 Diagnose. Opened when a P0 moves. Usually per-layer or per-tensor. Nobody watches these continuously. Every 100 steps
P2 Forensics. Per-parameter, per-expert, per-domain detail, for one investigation. On demand
Part I · Where to look

1. First screen

If you build one page, build this one: nine P0 signals, all per-step except the last.

Escalation order. Job state → loss → gradient norm and spikes → step time → memory → expert balance. Open the layer-level views only after that ordering fails to explain the symptom.

Cadence rule. Cheap alerting metrics run every step, tensor scans every 100 steps, evaluation every 0.5–2% of training. An anomaly triggers denser probes or a replay.

Comparison axis. If batch size changes, compare runs by cumulative tokens or estimated floating-point operations, never by step.

Part II · Every step

3. Loss

Let $R$ be the number of GPU ranks — one training process each. Rank $r$ contains $T_r$ token positions. For token $t$ on rank $r$, $\ell_{r,t}$ is its negative log-likelihood and $m_{r,t}$ is 1 for a valid target and 0 otherwise.

Global mean loss $L$.P0 Sum valid-token loss and valid-token count over all ranks, then divide.

$$L = \frac{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}\ell_{r,t}} {\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}}.$$

Use $L$ for convergence and scaling comparisons.

Local mean loss $L_r$.P1 The valid-token mean on rank $r$.

$$L_r = \frac{\sum_{t=1}^{T_r}m_{r,t}\ell_{r,t}} {\sum_{t=1}^{T_r}m_{r,t}}.$$

Omit a rank with no valid target; do not record it as zero.

Worst-rank loss $L_{\max}$.P0 The maximum local mean over ranks.

$$L_{\max}=\max_{1\le r\le R}L_r.$$

This is a maximum over GPU ranks, not over tokens or examples. It catches a bad worker or an unusual shard that $L$ averages away.

Loss by source and modality.P0 Let $\mu$ index a stable data source or modality, and $m^{(\mu)}_{r,t}$ be 1 when token $t$ on rank $r$ is a valid target belonging to $\mu$. Report the group loss with its token share.

$$L^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}\ell_{r,t}} {\sum_{r,t} m^{(\mu)}_{r,t}}, \qquad \pi^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}} {\sum_{r,t} m_{r,t}}.$$

A group holding a few percent of the tokens can regress for thousands of steps without moving $L$. Compare each group against its own history: absolute levels are not comparable across sources, whose token entropies differ.

Aggregation: do not average $L_r$ when valid-token counts differ. Reduce the loss sum and the token count separately, then divide.

4. Gradients and spikes

Let $g=(g_1,\ldots,g_P)$ contain all $P$ gradient elements. Measure after gradient accumulation and loss-scale removal, but before global clipping.

Global gradient norm $G_2$.P0 The Euclidean norm over all gradient elements.

$$G_2=\sqrt{\sum_{j=1}^{P}g_j^2}.$$

The primary stability signal, and usually the first thing to move in a failing run.

Clip rate.P0 With clip threshold $c$ over a window of $W$ recent steps:

$$\operatorname{Clip}=\frac{1}{W}\sum_{t}\mathbf{1}[G_{2,t}>c].$$

A low steady rate is normal. A sustained rise means clipping has become an unplanned learning-rate schedule.

Mean absolute gradient $G_{\mathrm{mean}}$.P1 The average absolute gradient element.

$$G_{\mathrm{mean}}=\frac{1}{P}\sum_{j=1}^{P}|g_j|.$$

Tracks typical element scale, and is less sensitive to one outlier than $G_{\max}$.

Maximum absolute gradient $G_{\max}$.P1 The largest absolute gradient element.

$$G_{\max}=\max_{1\le j\le P}|g_j|.$$

Detects localized explosion that $G_{\mathrm{mean}}$ dilutes away.

Gradient zero fraction $Z_g$.P1 Exact zeros divided by the element count.

$$Z_g=\frac{1}{P}\sum_{j=1}^{P}\mathbf{1}[g_j=0].$$

The indicator $\mathbf{1}[\mathcal{C}]$ is 1 when $\mathcal{C}$ holds and 0 otherwise. A rise means sparse paths, underflow, or parameters receiving no gradient. Report embeddings and expert parameters separately, where sparsity is expected and a change in it still matters.

Timing: record whether each gradient metric is scaled or unscaled, accumulated or per-microbatch, and before or after clipping. Norms measured at different points in the optimizer are not comparable.

Spike detection

For a positive scalar $x_t$ at step $t$, define $u_t=\log(x_t+\varepsilon)$ with numerical floor $\varepsilon>0$ and natural $\log$. Let $W_t$ contain earlier $u$-values.

Rolling median $q_t$ and deviation $D_t$.P1 A local baseline and a spread estimate that a spike cannot inflate.

$$q_t=\operatorname{median}(W_t), \qquad D_t=\operatorname{median}_{u\in W_t}|u-q_t|.$$

Robust spike score $z_t$.P1 Normalize the current deviation by $D_t$.

$$z_t=0.6745\frac{|u_t-q_t|}{D_t+\varepsilon}.$$

The factor 0.6745 calibrates the score for normally distributed log-values. Apply the detector separately to $L$ and $G_2$.

Co-spike indicator $C_t$.P0 Mark a step only when loss and gradient norm both spike.

$$C_t=\mathbf{1}[\text{loss spike at step }t]\, \mathbf{1}[\text{gradient-norm spike at step }t].$$

This is the one worth paging on. Track cumulative count and cumulative magnitude, not just the instantaneous flag.

Skip and replay counters.P1 Count skipped updates, replayed steps, and replays that did not reproduce the original loss.

The last one is the valuable counter: a replay that returns a different loss on identical inputs points at hardware, not data.

Thresholds: calibrate the window length and the $z_t$ threshold on stable runs. Do not tune them on a single failure.

5. System health

Let $\tau_r$ be the local step time on rank $r$, and $\tau=\max_r\tau_r$ the global wall time of the step.

Token throughput $\operatorname{TPS}$.P0 With $N_{\mathrm{tok}}$ the global valid tokens in one step:

$$\operatorname{TPS}=\frac{N_{\mathrm{tok}}}{\tau}.$$

Include data loading, forward, backward, optimizer, and synchronization in $\tau$.

Compute rate $\Phi$.P0 With $F_{\mathrm{step}}$ estimated operations per step and $D$ devices:

$$\Phi=\frac{F_{\mathrm{step}}}{D\tau}.$$

Keep the FLOP estimator fixed across compared runs; changing it changes the metric without changing the hardware.

Straggler score $S$.P1 Global step time over median local step time.

$$S=\frac{\tau}{\operatorname{median}_r(\tau_r)+\varepsilon}.$$

$S\approx1$ when ranks progress together. It rises when one slow rank sets the pace.

Peak memory.P0 Maximum allocated or reserved bytes in the interval, reduced with a maximum over ranks.

The max over ranks identifies the device closest to failure. Reset peak counters only at documented boundaries, or adjacent points describe different windows.

Allocated and reserved memory.P1 Allocated bytes are held by live tensors; reserved bytes are held by the allocator, including cached blocks.

A widening reserved-minus-allocated gap means fragmentation or an oversized cache, not a larger model.

Exposed collective wait $W_{\mathrm{comm}}$.P1 With $\tau_{\mathrm{wait}}$ the critical-path collective time not overlapped with computation:

$$W_{\mathrm{comm}}=\frac{\tau_{\mathrm{wait}}}{\tau}.$$

Report collective count and payload alongside it, to separate many small calls from one bandwidth-limited large call.

Device and host telemetry.P1 Utilization, power, temperature, clock, process memory, CPU pressure, page faults, network traffic.

These separate model regressions from host, thermal, allocator, and network failures — which is most of what a throughput drop turns out to be.

Timing: place device events around the real asynchronous wait and read them at an existing synchronization boundary. Adding host synchronization changes the overlap you are measuring.

Node counters: sample each network interface once per node. Reading it from every local rank multiplies the reported traffic.

Part III · Every 100 steps

6. Tensor probes

Let $x=(x_1,\ldots,x_N)$ be a flattened tensor with $N$ elements. One pass over memory can produce all of the statistics below at once.

Absolute maximum.P0 The largest absolute element.

$$\operatorname{AbsMax}(x)=\max_{1\le j\le N}|x_j|.$$

The fastest indicator of an outlier, overflow, or local explosion. At the model output it is P0 in its own right: it moves before the loss.

Root mean square.P1 The square root of the mean squared element value.

$$\operatorname{RMS}(x)=\sqrt{\frac{1}{N}\sum_{j=1}^{N}x_j^2}.$$

RMS measures energy scale and stays comparable across tensor sizes. Store the square mean $M_2(x)=\frac1N\sum_j x_j^2$ instead: ranks reduce the squared sum and element count separately, and RMS follows.

Absolute mean.P1 The average absolute element value.

$$\operatorname{AbsMean}(x)=\frac{1}{N}\sum_{j=1}^{N}|x_j|.$$

Typical scale without sign cancellation. It ignores a few large elements, so its gap from RMS is itself informative.

Zero fraction $Z_x$.P1 Exact zeros divided by $N$.

$$Z_x=\frac{1}{N}\sum_{j=1}^{N}\mathbf{1}[x_j=0].$$

Measures sparsity, underflow, and inactive paths.

Excess kurtosis $\kappa$.P2 With empirical mean $\mu$, normalize the fourth central moment by the squared variance.

$$\kappa= \frac{\frac{1}{N}\sum_{j=1}^{N}(x_j-\mu)^4} {\left(\frac{1}{N}\sum_{j=1}^{N}(x_j-\mu)^2\right)^2}-3.$$

Large positive $\kappa$ means heavy tails, a low-precision risk. Undefined at zero variance. Worth tracking on weights, rarely on activations.

Observation points. Embeddings, logits, query/key/value, normalized query and key, attention output, feed-forward activations, residual streams, expert inputs and outputs, parameter gradients, applied updates. Name forward activations and backward gradients distinctly — the pair is what makes the scan diagnostic.

Reading an explosion. Walk the backward absolute maximum inward from the output: model output, each block's pre-clip tensors, then attention and feed-forward internals. The first layer that jumps is the one to investigate.

Distributed reduction: aggregate sums and element counts before computing means, and aggregate maxima with a maximum reduction. Never average local maxima, or ratios whose denominators differ.

Relative update size

Relative update size $\rho$.P1 For parameter tensor $w$ and applied update $\Delta w$:

$$\rho=\frac{\operatorname{RMS}(\Delta w)} {\operatorname{RMS}(w)+\varepsilon}.$$

A persistent fall toward zero means ineffective updates; a sudden rise means an update large relative to the parameter scale. The ratio is comparable across layers and runs; the raw update norm is not.

Optimizer chain.P2 Record the raw gradient, normalized gradient, preconditioned direction, and applied update as separate tensors.

This locates the stage that introduces a scale or direction change. Too many series for a standing dashboard; turn it on for an investigation.

Naming: specify whether an optimizer tensor is before or after normalization, preconditioning, weight decay, learning-rate scaling, and clipping.

7. Expert balance

Let $E$ be the number of experts and $c_i$ the valid tokens sent to expert $i$, with mean load $\bar c=\frac1E\sum_i c_i$.

Imbalance ratio $I$ and maximum violation.P0 Compare the busiest expert with the mean.

$$I=\frac{\max_{1\le i\le E}c_i}{\bar c}, \qquad \operatorname{MaxVio}=\frac{\max_{1\le i\le E}c_i-\bar c}{\bar c}=I-1.$$

Perfect balance gives $I=1$ and $\operatorname{MaxVio}=0$; $\operatorname{MaxVio}=0.25$ means the busiest expert takes 25% more tokens than the mean. MaxVio is the form to put on a dashboard, because it is zero when nothing is wrong.

Shard imbalance.P0 The same ratio applied to expert-parallel shard loads.

Expert-level balance does not imply balanced communication groups, and it is the shard load that sets the step time.

Routing entropy $H$ and $H_{\mathrm{norm}}$.P1 With normalized loads $p_i=c_i/\sum_j c_j$:

$$H=-\sum_{i=1}^{E}p_i\log p_i, \qquad H_{\mathrm{norm}}=\frac{H}{\log E}.$$

$H_{\mathrm{norm}}=0$ is complete concentration, 1 is uniform routing. A sharp drop means the router is collapsing onto a few experts, usually before $I$ makes it obvious.

Per-expert load and router scores.P2 Per-expert token fractions, routing bias terms, top-$k$ margin distributions.

These answer which expert once the aggregate has already said that something is wrong.

Masking: exclude padding and invalid tokens, and skip ratios entirely when no valid token reaches the layer. An empty shard is not a measured zero.

8. Residual paths

Let $s\in\mathbb{R}^{d}$ be one token's residual-stream vector, $b\in\mathbb{R}^{d}$ the branch output added to it, and $a=s+b$ the updated stream.

Relative branch scale $R_b$.P0 Branch norm $N_b=\lVert b\rVert_2$ over stream norm $N_s=\lVert s\rVert_2$.

$$R_b=\frac{N_b}{N_s+\varepsilon}.$$

Small means a branch too weak to matter; large means a branch that overwrites the stream. Plotted across depth, it is the clearest single view of whether a deep model uses its depth. Report $N_s$ and $N_b$ too: the ratio cannot distinguish a shrinking branch from a growing stream.

For vectors $u$ and $v$, cosine similarity is

$$\cos(u,v)= \frac{u^\top v}{\lVert u\rVert_2\lVert v\rVert_2+\varepsilon}.$$

Block importance $B$ and angular distance $A$.P1 The directional change from $s$ to $a$, raw and normalized.

$$B=1-\cos(s,a), \qquad A=\frac{\arccos(\cos(s,a))}{\pi}.$$

$B=0$ when the update preserves direction, and $A$ lies in $[0,1]$. A block whose $B$ decays toward zero has stopped contributing, whatever its branch norm says.

BF16 no-op fraction $F_{\mathrm{noop}}$.P1 With $Q_{\mathrm{BF16}}(\cdot)$ rounding to bfloat16, count nonzero branch updates that rounded addition throws away.

$$F_{\mathrm{noop}}= \frac{1}{d}\sum_{j=1}^{d} \mathbf{1}\!\left[ Q_{\mathrm{BF16}}(s_j+b_j)=Q_{\mathrm{BF16}}(s_j) \ \land\ b_j\ne0 \right].$$

A large value means residual updates are being swallowed by precision. It grows as the stream norm grows, so watch it with $N_s$.

Gate saturation fraction.P1 For a branch scaled by a learned gate, let $\beta_j=\sigma(g_j/T)$ with logistic $\sigma$, gate $g_j$, temperature $T$. Report channels below a threshold $\theta$.

$$F_{\mathrm{gate}}(\theta)=\frac{1}{d}\sum_{j=1}^{d}\mathbf{1}[\beta_j<\theta].$$

Track a few thresholds, say $\theta\in\{0.05,0.1,0.25\}$. A branch whose gates have all closed contributes nothing and rarely reopens.

Aggregation: compute these per valid token, then report the mean and upper quantiles. Flattening all tokens and features together hides the token-level outliers you are looking for.

9. Modality paths

A multimodal run adds one failure mode: a modality degrading, or never contributing, while the aggregate curves look healthy. Three probes cover most of it; the fourth check — whether media inputs carry information at all — is an evaluation, in Section 10.

Token share $\pi^{(\mu)}$.P0 The fraction of valid targets belonging to modality $\mu$, defined in Section 3 alongside $L^{(\mu)}$.

Plot it next to the per-modality loss. A data-mix change, a packing bug, or a decoder that dropped a shard shows up here first, and explains loss movements that otherwise look like model regressions.

Media scale ratio $\gamma$.P0 Let $e^{(\mathrm{media})}$ be the embeddings an encoder and its projector hand to the backbone, and $e^{(\mathrm{text})}$ the text embeddings entering at the same point.

$$\gamma=\frac{\operatorname{RMS}(e^{(\mathrm{media})})} {\operatorname{RMS}(e^{(\mathrm{text})})+\varepsilon}.$$

Near 1, the two streams enter at the same scale. Persistently small, and the backbone can ignore media tokens at no cost to the loss — so it will. Large, and media tokens dominate the early layers. Both are projector problems more often than encoder problems.

Encoder gradient share $S_{\mathrm{enc}}$.P1 Squared gradient norm of the encoder parameters over the squared global norm.

$$S_{\mathrm{enc}}= \frac{\lVert g_{\mathrm{enc}}\rVert_2^{2}} {\lVert g\rVert_2^{2}}.$$

Compare against the encoder's share of parameters. Collapsing toward zero means the encoder has effectively frozen itself; far above its parameter share early points at the same projector scale problem $\gamma$ measures. The same decomposition per layer gives a gradient-contribution view.

Variable media length: samples carry different numbers of tiles or frames, so weight per-modality statistics by token count rather than averaging over samples. A rank that received no media has no measurement, not a zero.

Part IV · Every checkpoint

10. Evaluation

Let $M$ be the number of valid held-out tokens and $\ell_k$ the negative log-likelihood of token $k$.

Negative log-likelihood and perplexity.P0 Average held-out token losses, and exponentiate.

$$\operatorname{NLL}=\frac{1}{M}\sum_{k=1}^{M}\ell_k, \qquad \operatorname{PPL}=\exp(\operatorname{NLL}).$$

Perplexity adds no information over NLL, and is comparable only when tokenization and loss normalization are fixed.

Bits per byte.P0 With $N_{\mathrm{byte}}$ the source bytes covered by the held-out tokens:

$$\operatorname{BPB}=\frac{\sum_{k=1}^{M}\ell_k} {N_{\mathrm{byte}}\log 2}.$$

The right default for comparing runs: insensitive to tokenizer vocabulary and segmentation, which token-level perplexity is not.

Choice accuracy.P0 Over $Q$ questions with prediction $\hat a_q$ and reference $a_q$:

$$\operatorname{Accuracy}= \frac{1}{Q}\sum_{q=1}^{Q}\mathbf{1}[\hat a_q=a_q].$$

For multiple choice, select $\hat a_q$ by length-normalized option NLL. Freeze prompt construction and answer normalization for the life of the run.

Greedy generation.P0 Decode at temperature 0 and score after task-specific post-processing: exact match, pass@1, or a symbolic checker.

The cheapest evaluation that exposes failures likelihood scoring cannot see. Worth running on every key checkpoint, not only at the end.

Media gain $\Delta_{\mathrm{media}}$.P0 The same higher-is-better score computed with and without the media input.

$$\Delta_{\mathrm{media}}= Q_{\mathrm{with}}-Q_{\mathrm{without}}.$$

The only metric that proves a multimodal model uses its media input rather than answering from text priors. A capable model with $\Delta_{\mathrm{media}}\approx0$ is a unimodal model with extra cost.

Pass at $k$.P1 For one problem with $n$ samples, $c$ of them passing, and $k\le n$:

$$\widehat{\operatorname{pass@}k} =1-\frac{\binom{n-c}{k}}{\binom{n}{k}}.$$

If $n-c<k$, the estimate is 1. Pass@1 evaluates one attempt; larger $k$ measures coverage under repeated sampling.

Intersection over union.P1 For predicted region $\mathcal{P}$ and reference $\mathcal{G}$:

$$\operatorname{IoU}= \frac{|\mathcal{P}\cap\mathcal{G}|} {|\mathcal{P}\cup\mathcal{G}|}.$$

0 for no overlap, 1 for identical regions. Promote to P0 for a run whose target capabilities are grounding-heavy.

Averaged-weight evaluation.P1 Evaluate a running average of the weights alongside the raw ones.

Mid-run comparisons on raw weights are noisy enough to reverse a ranking between two recipes. Decide once which weight stream is the reference for decisions.

Comparability: version the dataset, tokenizer, prompt, decoding parameters, post-processing, and judge. A metric change is uninterpretable if its definition also changed.

Extrapolation: when a scaling fit predicts a larger run, report a bound outside the fitted range rather than a point estimate.

Part V · Practice

11. Common mistakes

Every one of these produces a plausible-looking curve, which is what makes them expensive.

MistakeWhat goes wrong
Everything is P0 If every panel can page you, none of them does
Wrong reduction group Data, tensor, pipeline, context, and expert-parallel groups have different semantics
Unclear maximum A maximum over tensor elements, tokens, examples, or GPU ranks gives four different metrics under one name
Ambiguous timing Gradients scaled, accumulated, clipped, or already applied are four different quantities
Duplicate recomputation Activation checkpointing may run a forward probe a second time, double-counting it
Empty shards Absence of data recorded as a measured zero drags every average toward zero
Padding counted as tokens Distorts loss, routing, and modality statistics in proportion to how much you pad
Over-smoothing A smoothed curve with no raw curve behind it hides exactly the short spikes you are watching for
High-cardinality labels Arbitrary parameter names and sample identifiers overwhelm online metric stores
Sensitive artifacts Raw samples and token-level traces must be opt-in, access-controlled, and short-lived

12. Keeping probes cheap

  1. Register once. Choose tensor locations while building the model.
  2. Gate early. On an unsampled step, skip the scan itself, not just the write.
  3. Scan once. Compute every local statistic for a tensor in one pass over memory.
  4. Reduce in batches. Group values by reduction type and issue one collective per group.
  5. Move only summaries. Keep full tensors on the device.
  6. Write asynchronously. Never put storage latency on the training path.

Let $K$ be the sampling interval in steps. Retain every $K$-th sample, every anomaly step, the warm-up and final steps, and 50–100 steps on each side of an anomaly. Small runs can use $K=1$; long runs use $K$ between 100 and 200 for expensive views, while cheap detectors keep running every step.

A detector cannot recover expensive measurements from before the event that triggered it. If that context matters, keep a short in-memory ring buffer, or replay the affected batch under denser probes.

Cadences here are initial settings, and priorities are defaults for a general run. Benchmark probe overhead on the target model, parallel configuration, and hardware before increasing any frequency.
