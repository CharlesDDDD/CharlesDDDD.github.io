This post gives a broad view of the metrics worth tracking during pretraining. Every lab has its own dashboard, so this list is necessarily opinionated. It can also help when testing a new architecture or optimizer: instead of looking only at loss, we can see how the change affects the model and the training system as a whole.探针（probe）是挂在训练上的一次测量。一次大规模训练会产生很多探针，难的从来不是多采几个，而是选出少数真正有用的信号。所以这里的每个指标除了定义、聚合方式和建议采样频率，还带一个优先级。

1. First screen第一屏

If you make only one dashboard, these signals are a useful starting point. Choose each cadence from its cost and the failure mode it is meant to catch.如果只做一个看板页，下面这些信号可以作为起点；每项频率应根据测量开销和它要捕捉的故障类型来定。

Shows stalls, slow workers, and communication slowdowns.卡顿、慢节点和通信退化。

System系统

Experts专家

Absolute max at the output输出端绝对值最大

Part II · Frequent checks第二部分 · 高频检查

3. Loss损失

Suppose the job has $R$ GPU ranks, with one training process on each rank. Rank $r$ has $T_r$ token positions. For token $t$, $\ell_{r,t}$ is the loss and $m_{r,t}$ is 1 when that token is a valid target, or 0 when it should be ignored.设 $R$ 为 GPU rank 数，每个 rank 是一个训练进程。rank $r$ 上有 $T_r$ 个 token 位置。对 rank $r$ 上的 token $t$，$\ell_{r,t}$ 是它的负对数似然，$m_{r,t}$ 在它是有效目标时取 1，否则取 0。

Global mean loss $L$.全局平均损失 $L$。P0 Add up the loss for every valid token on every rank, then divide by the number of valid tokens.先在所有 rank 上分别求有效 token 的 loss 之和与 token 计数，再相除。

$$L = \frac{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}\ell_{r,t}} {\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}}.$$

Use $L$ to track whether training is improving and to compare runs at different scales.收敛判断和 scaling 对比都用 $L$。

Local mean loss $L_r$.单 rank 平均损失 $L_r$。P1 Average the valid-token loss on one rank.rank $r$ 上有效 token 的平均。

$$L_r = \frac{\sum_{t=1}^{T_r}m_{r,t}\ell_{r,t}} {\sum_{t=1}^{T_r}m_{r,t}}.$$

If a rank has no valid targets, skip it. Do not record a zero.没有有效目标的 rank 直接跳过，不要记成 0。

Worst-rank loss $L_{\max}$.最差 rank 损失 $L_{\max}$。P0 Take the largest local mean across all ranks.在所有 rank 的局部均值里取最大。

$$L_{\max}=\max_{1\le r\le R}L_r.$$

This maximum is across GPU ranks, not tokens or examples. It can expose a bad worker or an unusual data shard hidden by the global average.这是对 GPU rank 取最大，不是对 token 或样本取最大。它能抓到被 $L$ 平均掉的坏 worker 或异常数据分片。

Loss by source and modality.按数据源与模态的损失。P0 Use $\mu$ for a fixed data source or modality. Set $m^{(\mu)}_{r,t}$ to 1 when a valid token belongs to that group. Report the group's loss and its share of all tokens together.设 $\mu$ 表示一个稳定的数据源或模态，当 rank $r$ 上的 token $t$ 是属于 $\mu$ 的有效目标时 $m^{(\mu)}_{r,t}$ 取 1。报这一组的 loss 时要同时报它的 token 占比。

$$L^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}\ell_{r,t}} {\sum_{r,t} m^{(\mu)}_{r,t}}, \qquad \pi^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}} {\sum_{r,t} m_{r,t}}.$$

A group with only a small share of the tokens can get worse for thousands of steps without noticeably changing $L$. Compare each group with its own past, not with other groups. Different sources can have very different baseline losses.只占几个百分点 token 的一组，可以连续退化几千步而完全不影响 $L$。每一组只跟自己的历史比：不同数据源的 token 熵不同，绝对数值之间没有可比性。

Combining ranks: if ranks have different numbers of valid tokens, do not average their $L_r$ values. Add the loss sums and token counts separately, then divide.聚合：各 rank 有效 token 数不同的时候，不要直接平均 $L_r$。要把 loss 之和与 token 计数分别 reduce，再相除。

4. Gradients and spikes梯度与尖峰

Let $g=(g_1,\ldots,g_P)$ contain all $P$ gradient values. Measure them after gradient accumulation and loss unscaling, but before global clipping.设 $g=(g_1,\ldots,g_P)$ 包含全部 $P$ 个梯度元素。测量点在梯度累积完成、去掉 loss scale 之后，但在全局裁剪之前。

Global gradient norm $G$.全局梯度范数 $G$。P0 The Euclidean norm over all gradient elements.所有梯度元素上的欧氏范数。

$$G=\sqrt{\sum_{j=1}^{P}g_j^2}.$$

This is the main stability signal. It often changes before the loss when a run starts to fail.最主要的稳定性信号，一次要崩的训练里通常是它先动。

Clip rate.裁剪率。P0 Count how often the gradient norm is above the clip threshold $G_{\mathrm{clip}}$ during the last $W$ steps. Here and below, $\mathbf{1}[\mathcal{C}]$ is 1 when $\mathcal{C}$ is true and 0 otherwise.取裁剪阈值 $G_{\mathrm{clip}}$，在最近 $W$ 步的窗口上。这里以及下文中，$\mathbf{1}[\mathcal{C}]$ 在条件 $\mathcal{C}$ 成立时为 1，否则为 0。

$$\text{clip rate}_t=\frac{1}{W} \sum_{i=t-W+1}^{t}\mathbf{1}[G_i>G_{\mathrm{clip}}].$$

A low, steady rate is normal. If it keeps rising, clipping is reducing the effective learning rate too often.维持在一个低值是正常的。持续上升则说明裁剪已经变成了一条你没有设计过的学习率调度。

Mean absolute gradient $G_{\mathrm{mean}}$.梯度绝对值均值 $G_{\mathrm{mean}}$。P1 The average absolute gradient element.所有梯度元素绝对值的平均。

$$G_{\mathrm{mean}}=\frac{1}{P}\sum_{j=1}^{P}|g_j|.$$

This shows the usual gradient size and is not easily skewed by one extreme value.反映典型的元素量级，比 $G_{\max}$ 更不容易被单个离群值带偏。

Maximum absolute gradient $G_{\max}$.梯度绝对值最大 $G_{\max}$。P1 The largest absolute gradient element.绝对值最大的那个梯度元素。

$$G_{\max}=\max_{1\le j\le P}|g_j|.$$

This catches one exploding value that can disappear in the mean.能抓到被 $G_{\mathrm{mean}}$ 稀释掉的局部爆炸。

Gradient zero fraction $Z_g$.梯度零元素比例 $Z_g$。P1 Exact zeros divided by the element count.严格等于 0 的元素数除以元素总数。

$$Z_g=\frac{1}{P}\sum_{j=1}^{P}\mathbf{1}[g_j=0].$$

If the zero fraction rises, some paths may be inactive, values may be underflowing, or some parameters may not be getting gradients. Report embeddings and expert parameters separately because they are sparse by design.它上升意味着稀疏路径、下溢，或者有参数完全拿不到梯度。embedding 和 expert 参数要单独报：这两处本来就该稀疏，但它的变化仍然有意义。

Record when you measure. Say whether a gradient is scaled, accumulated, or clipped. Values taken at different points in the optimizer cannot be compared.测量时点：每个梯度指标都要记清楚它是否带 scale、是累积后还是单个 microbatch、在裁剪前还是裁剪后。优化器里不同位置量出来的范数之间没有可比性。

Spike detection尖峰检测

The relationship between loss spikes, gradient growth, and residual-path scale has also been studied in public work on stable language-model pretraining [1].关于 loss spike、梯度增长与 residual-path 尺度之间的关系，已有公开的大模型稳定训练研究 [1]。

To find spikes in a positive metric $x_t$, first take $u_t=\log(x_t+\varepsilon)$. Here and in later formulas, $\varepsilon>0$ is a small number that prevents division by zero or $\log(0)$. Let $W_t$ be a window of earlier $u$ values.对第 $t$ 步的正标量 $x_t$，定义 $u_t=\log(x_t+\varepsilon)$。这里以及后面的公式中，$\varepsilon>0$ 是一个很小的数，用来避免除以 0 或计算 $\log(0)$。$W_t$ 是此前若干个 $u$ 值组成的窗口。

Rolling median $q_t$ and median absolute deviation $\operatorname{MAD}_t$.滑动中位数 $q_t$ 与中位绝对偏差 $\operatorname{MAD}_t$。P1 The median gives a recent baseline. $\operatorname{MAD}_t$ measures the usual variation without being pulled up by one spike.中位数给出近期基线，$\operatorname{MAD}_t$ 衡量通常的波动，而且不会被单个尖峰拉高。

$$q_t=\operatorname{median}(W_t), \qquad \operatorname{MAD}_t=\operatorname{median}_{u\in W_t}|u-q_t|.$$

Robust spike score $z_t$.稳健尖峰分数 $z_t$。P1 Compare the current value with that recent baseline:用 $\operatorname{MAD}_t$ 对当前偏差做归一化。

$$z_t=0.6745\frac{|u_t-q_t|}{\operatorname{MAD}_t+\varepsilon}.$$

The factor 0.6745 makes this behave like a standard z-score when the log values are normally distributed. Run it separately for loss and gradient norm.系数 0.6745 是按对数值服从正态分布来校准的。对 $L$ 和 $G$ 要各跑一套检测器。

Loss-gradient spike $C_t$.loss-梯度共同尖峰 $C_t$。P0 Set $C_t$ to 1 only when loss and gradient norm both spike.只有 loss 和梯度范数同时尖刺时，$C_t$ 才取 1。

$$C_t=\mathbf{1}[\text{loss spike at step }t]\, \mathbf{1}[\text{gradient-norm spike at step }t].$$

Use this for spike alerts. Also record how often it happens and how large the spikes are.用这个指标做尖峰报警。同时记录发生次数和尖峰大小。

Choose thresholds from healthy runs. Do not tune the window length or the $z_t$ cutoff around one failure.阈值：窗口长度和 $z_t$ 阈值要在稳定的训练上校准，不要拿一次故障去调。

5. System health系统健康

Let $\tau_r$ be the step time on rank $r$. The whole step finishes when the slowest rank finishes, so its wall time is $\tau=\max_r\tau_r$.设 $\tau_r$ 为 rank $r$ 上的本地单步耗时，$\tau=\max_r\tau_r$ 为这一步的全局墙钟时间。

Token throughput $\operatorname{TPS}$.token 吞吐 $\operatorname{TPS}$。P0 Divide the number of valid tokens in a step, $N_{\mathrm{tok}}$, by the step time:记 $N_{\mathrm{tok}}$ 为一步内全局的有效 token 数：

$$\operatorname{TPS}=\frac{N_{\mathrm{tok}}}{\tau}.$$

Include data loading, forward, backward, optimizer, and synchronization in $\tau$.$\tau$ 要把数据加载、前向、反向、优化器和同步全算进去。

Compute rate.算力速率。P0 If one step takes an estimated $F_{\mathrm{step}}$ operations across $D$ devices:记 $F_{\mathrm{step}}$ 为每步估计的运算量，$D$ 为设备数：

$$\text{compute rate}=\frac{F_{\mathrm{step}}}{D\tau}.$$

This is the estimated FLOPs per second on each device. Use the same FLOP estimate for every run you compare. Otherwise the number can change even when the hardware does not.这是每台设备每秒估计完成的 FLOP 数。参与对比的训练要用同一套 FLOP 估计口径；换了口径，硬件没变指标也会变。

Straggler score $S$.慢节点分数 $S$。P1 Divide the slowest rank's step time by the median rank's step time.全局单步耗时除以本地单步耗时的中位数。

$$S=\frac{\tau}{\operatorname{median}_r(\tau_r)+\varepsilon}.$$

$S\approx1$ means the ranks are moving together. A larger value means one slow rank is holding up the job.各 rank 步调一致时 $S\approx1$。一旦被某个慢 rank 卡住节奏，它就会上升。

Peak memory.显存峰值。P0 For each interval, record the largest allocated or reserved byte count across all ranks.统计区间内 allocated 或 reserved 的最大字节数，再跨 rank 取最大。

This shows which device is closest to running out of memory. Reset peak counters at fixed, documented points so neighboring samples cover the same length of time.跨 rank 取最大，才能定位到最接近挂掉的那张卡。峰值计数器只能在明确约定的边界上清零，否则相邻两个点描述的根本是不同的窗口。

Allocated and reserved memory.已分配与已预留显存。P1 Live tensors use allocated memory. The allocator holds reserved memory, including cached blocks.allocated 是活跃张量占用的字节；reserved 是分配器持有的字节，含缓存块。

If the gap between reserved and allocated memory keeps growing, look for fragmentation or an oversized cache.reserved 减 allocated 的差越拉越大，说明是碎片化或缓存过大，而不是模型变大了。

Communication wait $W_{\mathrm{comm}}$.暴露的集合通信等待 $W_{\mathrm{comm}}$。P1 Let $\tau_{\mathrm{wait}}$ be the time spent waiting for collective communication that does not overlap with compute:记 $\tau_{\mathrm{wait}}$ 为关键路径上没有和计算重叠的集合通信时间：

$$W_{\mathrm{comm}}=\frac{\tau_{\mathrm{wait}}}{\tau}.$$

Also record the number of calls and the bytes sent. That tells you whether the time comes from many small calls or one large, bandwidth-limited call.同时报集合通信的次数和数据量，才能区分「很多次小调用」和「一次被带宽卡住的大调用」。

Device and host stats.设备与主机遥测。P1 Utilization, power, temperature, clock speed, process memory, CPU load, page faults, and network traffic.利用率、功耗、温度、频率、进程内存、CPU 压力、缺页、网络流量。

Use these numbers as evidence when separating model-side slowdowns from host, cooling, memory, or network problems.这些信号可以作为证据，帮助区分模型侧变慢与主机、散热、内存或网络问题。

Measure without changing the work. Put device events around the real asynchronous wait and read them at an existing synchronization point. Adding a new host sync changes the overlap you are trying to measure.计时：device event 要卡在真正的异步等待两侧，并且在已有的同步点上读取。额外加一次主机同步，会直接改变你想测的那个重叠关系。

Count network traffic once per node. If every local rank reads the same network interface, the reported traffic will be multiplied.节点级计数器：每个网卡每节点只采一次。每个本地 rank 都读一遍，报出来的流量会翻好几倍。

Part III · Periodic and on-demand checks第三部分 · 周期性与按需检查

6. Tensor checks张量探针

For a tensor $x=(x_1,\ldots,x_N)$ with $N$ values, you can calculate all of the checks below in one pass through memory.设 $x=(x_1,\ldots,x_N)$ 是一个展平后含 $N$ 个元素的张量。下面这些统计量可以在一次内存遍历里一起算出来。

Absolute maximum.绝对值最大。P0 The largest absolute element.绝对值最大的那个元素。

$$\operatorname{AbsMax}(x)=\max_{1\le j\le N}|x_j|.$$

This can reveal an outlier, overflow, or local explosion. At the model output it can be useful as a primary signal because some numerical problems appear there before they affect aggregate loss.它可以发现离群值、溢出或局部爆炸。放在模型输出端时，它可以作为主要信号之一，因为部分数值问题会先在这里出现，再影响聚合 loss。

Root mean square.均方根 RMS。P1 Square each value, take the mean, then take the square root.元素平方均值再开方。

$$\operatorname{RMS}(x)=\sqrt{\frac{1}{N}\sum_{j=1}^{N}x_j^2}.$$

RMS shows the overall scale and can be compared across tensors of different sizes. To combine ranks correctly, add their squared sums and element counts first, then compute the RMS.RMS 衡量能量尺度，而且在不同大小的张量之间可比。落盘时存平方均值 $M_2(x)=\frac1N\sum_j x_j^2$ 更好：各 rank 分别 reduce 平方和与元素数，RMS 由它推出来即可。

Absolute mean.绝对值均值。P1 Take the absolute value of each element, then average them.所有元素绝对值的平均。

$$\operatorname{AbsMean}(x)=\frac{1}{N}\sum_{j=1}^{N}|x_j|.$$

This shows the usual size without positive and negative values canceling out. A large gap between the absolute mean and RMS suggests a few unusually large values.不受正负抵消影响的典型量级。它对少数大元素不敏感，所以它和 RMS 之间的差本身就是信息。

Zero fraction $Z_x$.零元素比例 $Z_x$。P1 Exact zeros divided by $N$.严格为 0 的元素数除以 $N$。

$$Z_x=\frac{1}{N}\sum_{j=1}^{N}\mathbf{1}[x_j=0].$$

A rising zero fraction can mean more sparsity, underflow, or an inactive path.衡量稀疏程度、下溢和失活路径。

Excess kurtosis $\kappa$.超额峰度 $\kappa$。P2 This measures how heavy the tails are. Here $\bar{x}$ is the tensor's mean.$\bar{x}$ 是张量的均值。用方差的平方去归一化四阶中心矩。

$$\kappa= \frac{\frac{1}{N}\sum_{j=1}^{N}(x_j-\bar{x})^4} {\left(\frac{1}{N}\sum_{j=1}^{N}(x_j-\bar{x})^2\right)^2}-3.$$

A large positive value means a few values sit far out in the tails, which can be risky at low precision. It is undefined if every value is the same. This is usually useful for weights, but rarely for activations.$\kappa$ 明显为正说明分布重尾，是低精度下的风险。方差为 0 时该量无定义。值得在权重上跟踪，激活上一般不必。

Where to measure. Useful points include embeddings, logits, query/key/value tensors, normalized queries and keys, attention outputs, feed-forward activations, residual streams, expert inputs and outputs, parameter gradients, and applied updates. Give activations and gradients different names so you can compare the forward and backward paths.观测点。embedding、logits、query/key/value、归一化后的 query 与 key、attention 输出、前馈激活、残差流、expert 的输入与输出、参数梯度、实际施加的更新。前向激活和反向梯度要用不同的名字——成对出现，这套扫描才有诊断力。

Finding an explosion. Start at the model output and compare the absolute maximum at selected block boundaries, then inspect attention or feed-forward internals near the first clear jump.怎么定位爆炸。从模型输出开始，比较若干选定 block 边界上的绝对值最大值，再检查第一个明显跳点附近的 attention 或前馈模块。

Combining ranks: add sums and element counts before computing a mean. For a maximum, take the largest value across ranks. Do not average local maxima or ratios with different denominators.分布式归约：先聚合求和项与元素计数再算均值，最大值要用 max 归约。绝不要去平均各 rank 的局部最大值，也不要平均分母不同的比值。

Relative update size相对更新幅度

Relative update size $\rho$.相对更新幅度 $\rho$。P1 For parameter tensor $w$ and applied update $\Delta w$:对参数张量 $w$ 和实际施加的更新 $\Delta w$：

$$\rho=\frac{\operatorname{RMS}(\Delta w)} {\operatorname{RMS}(w)+\varepsilon}.$$

If $\rho$ keeps falling toward zero, the updates may be too small to matter. A sudden rise means the update is large for that parameter. Unlike the raw update norm, this ratio can be compared across layers and runs.持续趋近于 0 说明更新已经不起作用；突然抬高说明更新相对参数尺度过大。这个比值在不同层、不同训练之间可比，而更新的绝对范数不可比。

Optimizer chain.优化器链路。P2 Record the raw gradient, normalized gradient, preconditioned direction, and final update separately.把原始梯度、归一化后的梯度、预条件后的方向、最终施加的更新当成四个独立张量分别记录。

If the scale or direction changes, these values tell you where it happened. They are too noisy for the main dashboard, so turn them on only while debugging.用来定位是哪一级引入了尺度或方向的变化。曲线太多，不适合常驻看板，排查时再打开。

Name the exact point. Say whether each optimizer value comes before or after normalization, preconditioning, weight decay, learning-rate scaling, and clipping.命名：优化器里的张量要写清楚它在归一化、预条件、weight decay、学习率缩放和裁剪之前还是之后。

7. Expert balance专家负载均衡

Suppose there are $E$ experts. Let $c_i$ be the number of valid tokens sent to expert $i$, and let $\bar c=\frac1E\sum_i c_i$ be the average load. Expert-load monitoring and balancing are publicly described in systems such as DeepSeek-V3 [2].设 $E$ 为 expert 数，$c_i$ 为路由到 expert $i$ 的有效 token 数，平均负载 $\bar c=\frac1E\sum_i c_i$。DeepSeek-V3 等公开系统已经介绍了 expert load 的监控与均衡 [2]。

Imbalance ratio $I$ and maximum violation (MaxVio).不均衡比 $I$ 与最大违反度（MaxVio）。P0 Compare the busiest expert with the average expert.把最忙的 expert 和平均值做比较。

$$I=\frac{\max_{1\le i\le E}c_i}{\bar c}, \qquad \operatorname{MaxVio}=\frac{\max_{1\le i\le E}c_i-\bar c}{\bar c}=I-1.$$

With perfect balance, $I=1$ and $\operatorname{MaxVio}=0$. For example, $\operatorname{MaxVio}=0.25$ means the busiest expert gets 25% more tokens than average. The zero-centered form can be convenient for visualization.完全均衡时 $I=1$、$\operatorname{MaxVio}=0$；例如 $\operatorname{MaxVio}=0.25$ 表示最忙的 expert 比平均多拿 25% 的 token。以 0 为均衡点的形式通常更便于可视化。

Shard imbalance.分片不均衡。P0 The same ratio applied to expert-parallel shard loads.把同一个比值用在 expert 并行的分片负载上。

Balanced experts do not always mean balanced communication groups. A busy shard can still slow down the whole step.单个 expert 均衡了，不等于通信组也均衡；真正决定单步耗时的是分片负载。

Expert-load entropy $H$ and $H_{\mathrm{norm}}$.专家负载熵 $H$ 与 $H_{\mathrm{norm}}$。P1 With normalized loads $p_i=c_i/\sum_j c_j$:取归一化负载 $p_i=c_i/\sum_j c_j$：

$$H=-\sum_{i=1}^{E}p_i\log p_i, \qquad H_{\mathrm{norm}}=\frac{H}{\log E}.$$

$H_{\mathrm{norm}}=0$ means all observed load is concentrated; 1 means the observed loads are even. This is entropy of token counts, not entropy of router logits or probabilities.$H_{\mathrm{norm}}=0$ 表示观测到的负载完全集中，1 表示负载均匀。这里计算的是 token 计数的熵，不是 router logits 或概率的熵。

Per-expert detail (optional).单 expert 细节（可选）。P2 When an aggregate balance metric moves, inspect a small set of per-expert load summaries and diagnostics appropriate to the routing algorithm.当聚合均衡指标发生变化时，可以按需查看少量单 expert 负载摘要，以及与所用路由算法相匹配的诊断量。

The useful details depend on the router design, so avoid treating one fixed set of scores as universal.有用的细节取决于 router 设计，不应把某一组固定分数当成通用标准。

Ignore padding and invalid tokens. If no valid token reaches a layer, skip its ratio. An empty shard is missing data, not a measured zero.掩码：要排除 padding 和无效 token；这一层一个有效 token 都没收到时，比值就整个跳过不记。空分片不是一个测出来的 0。

8. Residual paths残差路径

For one token, let $s\in\mathbb{R}^{d}$ be the residual stream before a block, where $d$ is its width. The block adds branch output $b\in\mathbb{R}^{d}$, giving $a=s+b$.对一个 token，设 $s\in\mathbb{R}^{d}$ 为进入 block 前的残差流，其中 $d$ 是它的宽度。block 加上分支输出 $b\in\mathbb{R}^{d}$，得到 $a=s+b$。

Relative branch scale $R_b$.分支相对尺度 $R_b$。P1 Compare the size of the branch, $N_b=\lVert b\rVert_2$, with the size of the stream, $N_s=\lVert s\rVert_2$.分支范数 $N_b=\lVert b\rVert_2$ 除以残差流范数 $N_s=\lVert s\rVert_2$。

$$R_b=\frac{N_b}{N_s+\varepsilon}.$$

A small value can indicate a weak branch; a large value can indicate a branch that dominates the stream. Plotting it by layer provides one view of how strongly blocks modify the model state. Also plot $N_s$ and $N_b$, because the ratio alone cannot tell whether the branch shrank or the stream grew.较小的值可能表示分支偏弱，较大的值可能表示分支主导了残差流。沿深度绘制这个比值，可以从一个角度观察各 block 改变模型状态的程度。$N_s$ 和 $N_b$ 也应分别展示，因为只看比值无法判断是分支缩小还是残差流增大。

For vectors $u$ and $v$, cosine similarity is对向量 $u$ 与 $v$，余弦相似度定义为

$$\cos(u,v)= \frac{u^\top v}{\lVert u\rVert_2\lVert v\rVert_2+\varepsilon}.$$

Block importance $B$ and angular distance $A$.块重要性 $B$ 与角距离 $A$。P1 These measure how much the block changes the stream's direction.从 $s$ 到 $a$ 的方向变化，分别给原始值和归一化值。

$$B=1-\cos(s,a), \qquad A=\frac{\arccos(\cos(s,a))}{\pi}.$$

$B=0$ means the direction did not change, and $A$ is always between 0 and 1. If a block's $B$ trends toward zero, it is doing little even when its branch norm looks large.更新不改变方向时 $B=0$，$A$ 落在 $[0,1]$ 内。$B$ 衰减到 0 的 block 已经不再有贡献了，不管它的分支范数看起来多大。

Reduced-precision addition check (optional).低精度加法检查（可选）。P2 On a small diagnostic sample, compare a residual addition in higher precision with the result at the training precision and count updates that disappear after rounding.可以在少量诊断样本上，对比更高精度与训练精度下的残差加法，统计舍入后消失的更新。

Use this only when investigating precision loss; the exact comparison should match the numeric formats and accumulation path of the implementation.这个检查只适合排查精度损失；具体比较方式应与实现采用的数值格式和累加路径一致。

Learned-gate distribution (optional).可学习门控分布（可选）。P2 For architectures with learned residual or branch gates, inspect broad distribution summaries or quantiles when branch contribution looks abnormal.对于带可学习 residual 或 branch gate 的架构，可以在分支贡献异常时按需查看门控值的分布摘要或分位数。

The useful statistic and interpretation depend on the gate parameterization. There is no architecture-independent target range or threshold.合适的统计量和解释方式取决于门控的参数化，不存在跨架构通用的目标区间或阈值。

Keep tokens separate. Compute these values for each valid token, then report the mean and high percentiles. If you flatten tokens and features together, unusual tokens can disappear in the average.聚合：这些量要逐个有效 token 算，再报均值和高分位。把所有 token 和特征拍平在一起，恰好会把你要找的 token 级离群点藏掉。

9. Modality paths模态路径

In a multimodal run, aggregate curves can look healthy while one modality gets worse. The checks below are optional examples for encoder-projector architectures, not universal metrics or target values. LLaVA is one public example of connecting a visual encoder to a language model through a learned projection [3].多模态训练中，聚合曲线可能看起来正常，而某个模态正在退化。下面是面向 encoder-projector 架构的可选示例，不是所有多模态模型都应采用的指标或目标值。LLaVA 是通过可学习投影连接视觉编码器与语言模型的公开例子之一 [3]。

Token share $\pi^{(\mu)}$.模态 token 占比 $\pi^{(\mu)}$。P0 The fraction of valid targets belonging to modality $\mu$, defined in Section 3 alongside $L^{(\mu)}$.属于模态 $\mu$ 的有效目标占比，定义见第 3 节，与 $L^{(\mu)}$ 一起给出。

Plot this beside the loss for each modality. A change can reveal a new data mix or an input-pipeline problem, either of which can move the loss without a change in the model itself.把它和按模态的 loss 画在一起。数据配比变化或输入流水线问题都可能先反映在这里，并解释一些看似由模型退化造成的 loss 波动。

Optional example: media scale ratio $\gamma$.可选示例：media 特征尺度比 $\gamma$。P1 For an encoder-projector model, let $e^{(\mathrm{media})}$ be the projected media embeddings entering the language model, and $e^{(\mathrm{text})}$ the text embeddings entering at a comparable point.对 encoder-projector 模型，记 $e^{(\mathrm{media})}$ 为进入语言模型的投影后 media embedding，$e^{(\mathrm{text})}$ 为在可比位置进入模型的文本 embedding。

$$\gamma=\frac{\operatorname{RMS}(e^{(\mathrm{media})})} {\operatorname{RMS}(e^{(\mathrm{text})})+\varepsilon}.$$

Interpret this ratio against the same model's baseline and normalization scheme. A large change can motivate checking the connector and surrounding layers, but there is no universal ideal value.应结合该模型自身的历史基线和归一化方式解释这个比值。明显变化可以提示检查连接层及其相邻模块，但不存在通用的理想数值。

Optional example: encoder gradient share $S_{\mathrm{enc}}$.可选示例：编码器梯度占比 $S_{\mathrm{enc}}$。P2 For a trainable encoder, divide its squared gradient norm by the squared global norm.对参与训练的编码器，用其梯度范数平方除以全局梯度范数平方。

$$S_{\mathrm{enc}}= \frac{\lVert g_{\mathrm{enc}}\rVert_2^{2}} {\lVert g\rVert_2^{2}}.$$

Use changes relative to comparable runs as a debugging clue, not as a universal health threshold. Break it down by layer only when the aggregate signal motivates a closer look.把它相对可比训练的变化当作诊断线索，而不是通用健康阈值；只有聚合信号值得继续追查时，再按层展开。

Media length varies. Samples can contain different numbers of media tokens, so weight these metrics by token count instead of averaging samples. If a worker gets no media, it has no measurement; do not record a zero.media 长度可变：不同样本可能包含不同数量的 media token，因此应按 token 数加权，而不是直接对样本求平均。某个 worker 没收到 media 时表示「没有测量值」，不是 0。

Part IV · Milestone evaluation第四部分 · 里程碑评测

10. Evaluation评测

On the held-out set, let $M$ be the number of valid tokens and $\ell_k$ the loss for token $k$.设 $M$ 为留出集中有效 token 的数量，$\ell_k$ 为第 $k$ 个 token 的负对数似然。

Negative log-likelihood and perplexity.负对数似然与困惑度。P0 Average the held-out token losses. Perplexity is the exponential of that average.对留出集 token 的 loss 取平均，再取指数。

$$\operatorname{NLL}=\frac{1}{M}\sum_{k=1}^{M}\ell_k, \qquad \operatorname{PPL}=\exp(\operatorname{NLL}).$$

Perplexity is just another way to show NLL. Compare it only when the tokenizer and loss normalization stay the same.困惑度相对 NLL 没有增加任何信息，而且只有在分词方式和 loss 归一化都固定时才可比。

Bits per byte.每字节比特数 BPB。P0 Let $N_{\mathrm{byte}}$ be the number of source bytes covered by those tokens:记 $N_{\mathrm{byte}}$ 为这些留出 token 所覆盖的原始字节数：

$$\operatorname{BPB}=\frac{\sum_{k=1}^{M}\ell_k} {N_{\mathrm{byte}}\log 2}.$$

If tokenizers differ, bits per byte is safer than token-level perplexity because it does not depend on vocabulary size or token boundaries.跨训练对比时的默认选择：它对分词器的词表和切分方式不敏感，而 token 级困惑度做不到这一点。

Choice accuracy.选择题准确率。P0 For $Q$ questions, compare each prediction $\hat a_q$ with the correct answer $a_q$:共 $Q$ 道题，预测为 $\hat a_q$，参考答案为 $a_q$：

$$\operatorname{Accuracy}= \frac{1}{Q}\sum_{q=1}^{Q}\mathbf{1}[\hat a_q=a_q].$$

For multiple choice, score each option with length-normalized NLL. Do not change the prompt format or answer cleanup during the run.多选题用长度归一化后的选项 NLL 来选 $\hat a_q$。prompt 的拼法和答案归一化方式，在整个训练周期内都不要再改。

Greedy generation.贪心生成。P0 Generate at temperature 0, clean up the answer for the task, then score it with exact match, pass@1, or a symbolic checker.temperature 取 0 解码，按任务做完后处理再打分：exact match、pass@1，或者符号判定器。

This can catch problems that likelihood scores miss. When its cost fits the evaluation budget, run it at more than just the final checkpoint.它可以发现似然打分没有暴露的问题；如果评测预算允许，可以不只在最终 checkpoint 上运行。

Media gain $\Delta_{\mathrm{media}}$.media 增益 $\Delta_{\mathrm{media}}$。P0 Compute the same score once with the media input and once without it.同一个「越高越好」的指标，分别在有 media 输入和去掉 media 输入的条件下各算一次。

$$\Delta_{\mathrm{media}}= \operatorname{score}_{\mathrm{with\ media}}- \operatorname{score}_{\mathrm{without\ media}}.$$

This ablation helps test whether media changes the measured behavior. If $\Delta_{\mathrm{media}}\approx0$, the evaluation found no measurable benefit from media under that setup; it does not prove that the model never uses media.这个消融有助于判断 media 是否改变了被测行为。如果 $\Delta_{\mathrm{media}}\approx0$，只能说明在当前评测设置下没有测到 media 带来的收益，不能据此证明模型从不使用 media。

Pass at $k$.pass@$k$。P1 For one problem, sample $n$ answers. If $c$ pass and $k\le n$:对某道题采样 $n$ 次，其中 $c$ 次通过，取 $k\le n$：

$$\widehat{\operatorname{pass@}k} =1-\frac{\binom{n-c}{k}}{\binom{n}{k}}.$$

If $n-c<k$, the estimate is 1. Pass@1 measures one attempt. Larger values of $k$ ask whether repeated sampling can find a correct answer. This estimator is described in the Codex evaluation paper [5].当 $n-c<k$ 时估计值为 1。pass@1 衡量一次作答的水平，$k$ 更大时衡量的是重复采样下的覆盖率。这个估计量见 Codex 的公开评测论文 [5]。

Intersection over union.交并比 IoU。P1 For predicted region $\mathcal{P}$ and reference $\mathcal{G}$:对预测区域 $\mathcal{P}$ 与参考区域 $\mathcal{G}$：

$$\operatorname{IoU}= \frac{|\mathcal{P}\cap\mathcal{G}|} {|\mathcal{P}\cup\mathcal{G}|}.$$

A score of 0 means no overlap; 1 means the regions match exactly. Make this P0 when grounding is a main goal of the run.完全不重叠为 0，完全重合为 1。如果这次训练的目标能力以 grounding 为主，就把它提到 P0。

Keep the evaluation fixed. Version the dataset, tokenizer, prompt, decoding settings, answer cleanup, and judge. If the definition changes, you cannot tell whether the model changed.可比性：数据集、分词器、prompt、解码参数、后处理和判分器都要有版本号。定义跟着一起变了的指标，涨跌都没法解释。

Optional reporting practice. Predictions outside the range used to fit a scaling curve are extrapolations. Label them explicitly and report uncertainty rather than presenting one number as a measurement; this is a general regression caution [4].可选报告方式。超出 scaling 曲线拟合区间的预测属于外推，应明确标注并报告不确定性，而不要把单个预测值写成实测结果；这是通用的回归分析注意事项 [4]。

11. Common mistakes常见错误

These mistakes are easy to miss because the charts can still look reasonable.下面每一条都会画出一条看起来挺合理的曲线——这正是它们代价高的原因。

Mistake错误What goes wrong会出什么问题
Everything is P0什么都是 P0 Too many alerts become noise, so people stop trusting them如果每块面板都能把你叫醒，那就等于没有一块能
Wrong reduction group归约组用错 Each parallel group combines a different set of valuesdata、tensor、pipeline、context、expert 并行组的语义各不相同
Unclear maximum没说清最大值是对谁取的 Say whether the maximum is over tensor values, tokens, examples, or GPU ranks对张量元素、token、样本、GPU rank 取最大，是同一个名字下的四个不同指标
Ambiguous timing测量时点含糊 Scaled, accumulated, clipped, and applied gradients are different values带 scale 的、累积后的、裁剪后的、已施加的梯度，是四个不同的量
Duplicate recomputation重复计算 Activation checkpointing may run a forward check twice and count it twice激活重算会让前向探针跑第二遍，导致重复计数
Empty shards空分片 Recording missing data as zero pulls every average down把「没有数据」记成测量值 0，会把所有平均值往下拽

Over-smoothing过度平滑 A smoothed curve can hide short spikes; keep the raw curve too平滑曲线背后不留原始曲线，藏掉的恰好是你要找的短尖峰
Too many label values高基数标签 Raw parameter names and sample IDs can overwhelm the metric store任意的参数名和样本 ID 会把在线指标存储撑爆
Sensitive artifacts敏感产物 Keep raw samples and token traces off by default, restrict access, and delete them soon原始样本和 token 级 trace 必须默认关闭、有权限控制、短期保留

12. Keeping monitoring cheap控制探针开销

  1. Choose the tensor locations while building the model, and register each hook once.只注册一次。在搭模型的时候就把观测点定好。
  2. If a step is not being sampled, skip the scan itself, not just the write.尽早判断。不采样的那些步，要跳过扫描本身，而不只是跳过写盘。
  3. Compute all local statistics for a tensor in one pass through memory.只扫一遍。一个张量的所有局部统计量，在一次内存遍历里全部算完。
  4. Group values by reduction type and send one collective for each group.批量归约。按归约类型分组，每组只发一次集合通信。
  5. Move summaries only. Keep full tensors on the device.只搬摘要。完整张量留在设备上。
  6. Write results in the background so storage does not slow down training.异步落盘。绝不要把存储延迟放到训练主路径上。

Let $K$ be the number of steps between samples. Keep regular samples, warm-up and final samples, unusual events, and a bounded context window around each event. Choose both $K$ and the window size from measured overhead and the available storage budget; cheap alerts can remain frequent while expensive checks stay sparse.设 $K$ 为采样间隔。可以保留常规样本、warm-up 与收尾样本、异常事件，以及每个事件附近一个有界的上下文窗口。$K$ 和窗口大小都应根据实测开销与存储预算决定；便宜的报警可以保持高频，昂贵检查则保持稀疏。

An alert cannot recover detailed measurements from before it fired. If that context matters, retain a bounded buffer of low-cost summaries and temporarily increase diagnostic sampling after an event.检测器无法补回触发前没有采集的昂贵测量。如果这段上下文重要，可以保留一个有界的低成本摘要缓冲，并在事件发生后临时提高诊断采样密度。
