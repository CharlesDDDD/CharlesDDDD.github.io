Pathloop: Making a Looped MoE Take Different Paths

A looped mixture-of-experts runs the same layers three times. Does it do anything different on each pass?

Chunyuan Deng · August 2026 · project log

TL;DR

We fine-tune a 30B mixture-of-experts model with its middle layers looped three times, which turns 48 layers into 96 executed ones. Looping helps, but not where you would guess: on the coding data we train on it adds nothing, and on the nine benchmarks we never train on it does not raise the peak either — it holds the peak. Plain fine-tuning gains five points out-of-domain and then gives all of them back; the looped runs keep most of theirs. Reading the probes then showed why the loop is weaker than it should be — the second and third passes are near-copies of each other. They route to nearly the same experts and barely change the representation. The loop is not building three different paths through the model; it is building one path and two near-repeats. Pathloop is our attempt to force the passes apart by making the router sample a little during training, and then letting the three passes compete. It is implemented and a first run is in progress.

I. Problem

A mixture-of-experts layer scores every expert for each token but evaluates only the best $k$ of $E$:

$s_t = \mathrm{softmax}\big(W_r h_t\big) \in \mathbb{R}^E, \qquad \mathcal{S}_t = \operatorname*{arg\,top-}_{k} s_t, \qquad \mathrm{MoE}(h_t) = \sum_{e \in \mathcal{S}_t} \frac{s_{t,e}}{\sum_{e' \in \mathcal{S}_t} s_{t,e'}}\, f_e(h_t)$
(1)

$\mathcal{S}_t$ is the token's path — which 8 of 128 experts it passes through. $f_e(h) = W^e_{\text{down}}\big(\sigma(W^e_{\text{gate}}h) \odot W^e_{\text{up}}h\big)$.

Two facts about $\mathcal{S}_t$ motivate the project. First, unselected experts are never evaluated:

$\dfrac{\partial \mathcal{L}}{\partial \theta_e} = 0 \quad \text{for all } e \notin \mathcal{S}_t$
(2)

so fine-tuning cannot re-route: only $W_r$ moves, and slowly. Measured in §VI — one epoch shifts the routing distribution by about 2%.

Second, running the same layers $K$ times should yield $K$ distinct paths $\mathcal{S}^0_t, \dots, \mathcal{S}^{K-1}_t$. It does not (§VI). Pathloop is an attempt to force them apart.

II. Looped SFT

$x \in \mathbb{N}^T,\; d = 2048$input tokens; model width
$T_0,\dots,T_{L-1},\; L = 48$transformer layers
$[a,b) = [12,36),\; W = 24$looped window and its width
$K = 3$passes through the window
$E = 128,\; k = 8$experts per layer; experts used per token
$g_1,\dots,g_{K-1} \in \mathbb{R}^d$gates, one per pass after the first, initialised to $0$
$z = h + \mathrm{Attn}_\ell\big(\mathrm{Norm}(h)\big), \qquad T_\ell(h) = z + \mathrm{MoE}_\ell\big(\mathrm{Norm}(z)\big)$
(3)
$h_{-1} = \big(T_{a-1} \circ \cdots \circ T_0\big)\big(\mathrm{Embed}(x)\big), \qquad F = T_{b-1} \circ \cdots \circ T_a$
(4)
$u_\tau = F\big(h_{\tau-1}\big), \qquad h_\tau = \begin{cases} u_0 & \tau = 0 \\[3pt] h_{\tau-1} + g_\tau \odot \big(u_\tau - h_{\tau-1}\big) & 1 \leq \tau \leq K-1\end{cases}$
(5)
$\text{logits} = W_U\,\mathrm{Norm}\Big(\big(T_{L-1} \circ \cdots \circ T_b\big)\big(h_{K-1}\big)\Big)$
(6)
$\text{executed depth} \;=\; a + KW + (L-b) \;=\; 12 + 72 + 12 \;=\; 96$
(7)

Pass 0 is ungated, taken in full. Weights are shared across passes; only the $2d$ gate values are new.

Consequence A. At $g_\tau = 0$, (5) gives $h_\tau = h_{\tau-1}$, so $h_{K-1} = u_0 = F(h_{-1})$ and the looped model equals the original bit-for-bit. Training starts from a known-good point; the extra passes start as exact no-ops.

Consequence B. $W_r$ is shared across passes, so pass $\tau$ routes differently from pass $\tau-1$ only if the router's input moved enough to reorder its top $k$. From (5),

$h_\tau - h_{\tau-1} = g_\tau \odot \big(u_\tau - h_{\tau-1}\big) \;\xrightarrow[\;\|g_\tau\| \to 0\;]{}\; 0 \qquad\Longrightarrow\qquad \mathcal{S}^\tau_t = \mathcal{S}^{\tau-1}_t$
(8)

Small gates force the passes to route identically. §VI measures $\|g_\tau\|_{\text{rms}} \approx 0.02$–$0.06$ after a full epoch, and finds exactly this.

III. Pathloop

Training-time only: replace $\mathcal{S}_t$ in (1) with a partly sampled set. Inference is unchanged plain top-$k$.

$k = p + q, \qquad \mathcal{P}_t = \operatorname*{arg\,top-}_{p}\big\{s_{t,e} : e \in \mathcal{S}_t\big\}$
(9)
$\beta : \{1,\dots,E\} \to \{0,\dots,K\!-\!1\}, \qquad \mathcal{T}^\tau_t = \big\{e \notin \mathcal{S}_t \;:\; \beta(e) = \tau\big\}$
(10)
$\mathcal{Q}^\tau_t = \operatorname*{arg\,top-}_{q}\Big\{\log s_{t,e} - \log(-\log u_e) \;:\; e \in \mathcal{T}^\tau_t\Big\}, \quad u_e \sim \mathcal{U}(0,1)$
(11)
$\tilde{\mathcal{S}}^\tau_t = \mathcal{P}_t \cup \mathcal{Q}^\tau_t, \qquad \big|\tilde{\mathcal{S}}^\tau_t\big| = p + q = k, \qquad \tilde{w}_{t,e} = \frac{s_{t,e}}{\sum_{e' \in \tilde{\mathcal{S}}^\tau_t} s_{t,e'}}$
(12)

$\beta$ is redrawn every step and gives each pass a disjoint pool, so the $K$ passes explore different candidates rather than colliding. (11) is Gumbel top-$q$: sampling $q$ experts without replacement with probability proportional to $s_t$. Cost is unchanged — still $k$ experts per token — but the $q$ sampled experts now receive gradient, which (2) otherwise forbids.

The loop supplies $K$ states per token for free. Score each through the output head and compare them:

$R_\tau(t) = \log P\big(y_t \mid W_U \mathrm{Norm}(h_\tau)_t\big), \qquad A_\tau(t) = R_\tau(t) - \frac{1}{K-1}\sum_{\tau' \neq \tau} R_{\tau'}(t)$
(13)

$A_\tau$ compares a pass against its own siblings, which saw the same token in the same context — so token difficulty cancels and no baseline model is needed. By construction $\sum_\tau A_\tau(t) = 0$.

$\mathcal{L}_{\text{path}} = -\sum_{\tau} \mathbb{E}_t\Big[A_\tau(t)\,\log \pi_\tau\big(\mathcal{Q}^\tau_t \mid h_{\tau-1}\big)\Big], \qquad \mathcal{L}_{\text{ladder}} = -\sum_\tau \frac{\lambda(\tau+1)}{K}\,\mathbb{E}_t\big[R_\tau(t)\big]$
(14)

$\pi_\tau$ is the router's probability of having drawn that set, as an ordered draw without replacement. $\mathcal{L}_{\text{ladder}}$ uses the label, not agreement between passes: the cheapest way to make passes agree is $g_\tau \to 0$, the degenerate solution the gates already sit next to. Both terms are switched off wherever $q = 0$, so $q = 0$ is exactly plain looped SFT.

Tier 1 samples and measures $R_\tau, A_\tau$ without training on them — it asks whether the comparison carries signal before anything is built on it. Tier 2 adds (14). $q$ follows a schedule and returns to $0$ before training ends, so the final model is trained under the policy it is served with.

IV. Setup

Base model is a 30B-parameter mixture-of-experts with 3B active per token: 48 layers, 128 experts per layer, top-8 routing. The loop covers layers 12–35, repeated three times.

We fine-tune on Ling-Coder, a 400k-example coding instruction set, for one epoch (415 steps). A math dataset (OT3) is the alternative we have also used; everything reported here is Ling-Coder.

We evaluate on 14 benchmarks with greedy decoding. Because we fine-tune on coding data, the benchmarks split into two groups, and keeping them apart turns out to matter more than any single number:

  • In-domain (5) — HumanEval, HumanEval+, MBPP, MBPP+, LiveCodeBench. Coding, the same skill we train.
  • Out-of-domain (9) — GSM8K, MATH500, MATH500-flex, AMC23, AIME24, AIME25, MMLU-Pro, GPQA-Diamond, IFEval. Math, knowledge and instruction-following, none of which appear in the training data.

Splitting the benchmarks changes the conclusion

In-domain, looping does nothing. Fine-tuning lifts coding from 59.6 to about 71, and all three fine-tuned arms land within 0.6 of each other. Whatever the loop contributes, it is not coding ability.

Out-of-domain is where the arms separate, but by less than a final-checkpoint comparison suggests. At its best checkpoint plain fine-tuning reaches 42.7 — a real gain of five points over the base model. Standard-gate looping reaches 43.2, barely ahead. Only the fast-gate arm opens a clear margin, at 45.3.

This matters because comparing final checkpoints tells a much flattering story: there, plain fine-tuning scores 37.5 against 40.3 and 40.9 for the looped arms. That gap is almost entirely plain fine-tuning having fallen back to the base model by step 415, not the looped arms having learned more.

It is retention, not a higher peak

Evaluating at three checkpoints shows what is actually happening. Out-of-domain, every arm peaks at step 149 — the earliest checkpoint we saved — and declines from there. Plain fine-tuning declines all the way back to the base model. The looped arms decline more slowly and stop above it.

VI. What the probes say

We log internal statistics every 25 steps. Two of them reframed the project.

The gates open slowly, and they matter

The router barely moves during fine-tuning

This is the assumption pathloop is built on, and the probes confirm it. Over a full epoch, the routing distribution is almost unchanged:

A full epoch of fine-tuning moves the router by a couple of percent. Routing established in pretraining survives fine-tuning essentially intact — which is exactly why an intervention that forces the router to try alternatives might be worth something.

The three loop passes are not three different paths

This is the measurement that matters most, and the one that reframed the project. The probes are keyed by executed position, not by parameter layer, so all 96 executed layers are recorded separately. Parameter layer $L$ appears at executed positions $L$, $L+24$ and $L+48$ — once per loop pass. Comparing those three tells us directly what each pass does with the same weights.

Why this happens, and why it matters

Pass 0 is ungated and always applied in full, so it does real work. Passes 1 and 2 are multiplied by a gate that reaches only about 0.02–0.06, so they nudge the state rather than transform it. A nudged state produces nearly the same router scores, so it selects nearly the same experts — and the two nudges land in nearly the same place as each other.

This is a problem for pathloop specifically. Its whole mechanism is to compare passes against each other and reward the better one. If the passes are copies, every comparison is between identical things, the advantage $A_\tau$ is zero, and there is nothing to learn from. We confirmed this directly: in short test runs the spread of reward across passes sat at roughly $10^{-7}$, i.e. exactly zero.

It is also a caveat on the claim of "96 effective layers". By this measurement the model behaves closer to 48 real layers plus two cheap refinement passes.

One honest limit on the table above: these are distributional statistics — entropy, top-1 probability, load spread. Two genuinely different sets of 8 experts could in principle produce the same entropy. The statistics being identical to four decimals is strong evidence the passes route the same way, but it is not proof. We have since added a metric that compares the selected expert sets directly, token by token, and reports what fraction of each token's 8 experts carries over from one pass to the next. The current run is the first to record it.

VII. Where pathloop stands

In progress. Pathloop is implemented and unit-tested, and the first tier-1 run on Ling-Coder is training now. No pathloop results yet.

Building it surfaced five bugs, every one silent — nothing crashed, and each would have produced a clean-looking run that measured nothing:

  • The sampled experts were given roughly a third of their correct weight, because two different normalizations were being mixed.
  • The training step counter never advanced under our trainer, pinning exploration at zero for an entire run while the logs reported it as active.
  • The exploration schedule never wound back down, because the trainer does not expose a total step count.
  • Even with that fixed, an off-by-one meant exploration reached zero one step after training ended, so the model never trained under the policy it is served with.
  • The tier-2 auxiliary loss ignored the schedule, so tier 1 and tier 2 differed from step 0 by an amount that had nothing to do with the idea being tested.

The run in progress places exploration in the middle of training — off for the first 100 steps, easing to $q{=}1$, full at $q{=}2$ from 150 to 300, then easing back to zero by 350. The shaded band in Figure 2 shows why: exploring before the gates open would perturb passes that are still doing nothing.

The question this run answers is narrow and prior to everything else: once the gates are open, do the three passes ever become different enough to compare? If the reward spread lifts off the floor, the comparison is real and tier 2 is worth training. If it stays at zero through the exploration window, then the passes are copies no matter what the router does, and the honest next step is not more pathloop but changing how the loop is built — starting the gates away from zero, so the passes are distinct from the beginning.
