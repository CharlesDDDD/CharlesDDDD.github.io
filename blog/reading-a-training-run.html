Reading a Training Run

Metrics, definitions, aggregation semantics, and sampling cadence

Chunyuan Deng · September 2026

A probe is a measurement attached to training. The monitoring stack has three levels: per-step health metrics, periodic tensor diagnostics, and checkpoint evaluation.

A note on “rank.” In this post, a rank is one process in a distributed training job. It does not mean matrix rank.

1. Start with cadence

Sampling frequency is determined by probe cost and required alert latency.

Cadence What to collect Purpose
Every step Mean and worst-rank loss, gradient norm, learning rate, step time, throughput, maximum memory across ranks, skip/retry state, one Mixture-of-Experts imbalance Alerting
Every 10 steps Loss by data source, allocator state, CPU and network summaries Short trends
Every 100 steps Layer activations and gradients, optimizer tensors, residual paths, detailed routing Diagnosis
Every 0.5–2% of training Small held-out language-modeling suite Generalization
Key checkpoints Generation, long-context, multiple-choice, and multimodal evaluation Model selection
On an event Dense samples around a loss spike, gradient spike, slowdown, or memory jump; replay when earlier tensor detail is needed Root cause

If batch size changes across runs, place cumulative tokens or estimated floating-point operations on the horizontal axis. A step is not a stable unit of compute. For time and memory, keep both a typical value and the maximum across ranks; the average can hide the machine that limits the run.

2. Core optimization health

Loss

Let $R$ be the number of distributed ranks. Rank $r$ contains $T_r$ token positions. For token $t$ on rank $r$, let $\ell_{r,t}$ be its negative log-likelihood and let $m_{r,t}$ be 1 for a valid target and 0 otherwise. The globally weighted loss is

$$L = \frac{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}\ell_{r,t}} {\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}}.$$

Here, $L$ is the global mean loss. The local mean on rank $r$ is

$$L_r = \frac{\sum_{t=1}^{T_r}m_{r,t}\ell_{r,t}} {\sum_{t=1}^{T_r}m_{r,t}}, \qquad L_{\max}=\max_{1\le r\le R}L_r.$$

$L_{\max}$ is the largest rank-level mean. It is not the largest token loss or example loss unless the logger explicitly says so. A rank with no valid target should be omitted, not recorded as zero. Plot $L$ and $L_{\max}$ together: the first shows progress; the second reveals a bad worker or an unusual shard.

Avoid the mean of means. If ranks contain different numbers of valid tokens, averaging the values $L_r$ gives each rank equal weight. Sum the numerators and denominators first, as in the definition of $L$.

Gradient scale

Let $g=(g_1,\ldots,g_P)$ be the concatenation of all $P$ gradient elements after accumulation and loss-scale removal, but before global clipping. The index $j$ below selects one gradient element. Useful summaries are

$$G_2=\sqrt{\sum_{j=1}^{P}g_j^2}, \qquad G_{\mathrm{mean}}=\frac{1}{P}\sum_{j=1}^{P}|g_j|, \qquad G_{\max}=\max_{1\le j\le P}|g_j|, \qquad Z_g=\frac{1}{P}\sum_{j=1}^{P}\mathbf{1}[g_j=0].$$

$G_2$ is the global gradient L2, or Euclidean, norm. $G_{\mathrm{mean}}$ is the mean absolute gradient. $G_{\max}$ is the largest absolute element. $Z_g$ is the fraction of gradient elements equal to zero, and $\mathbf{1}[\cdot]$ is the indicator function. Of these, $G_2$ is usually the clearest early warning.

Spikes

A spike detector turns a noisy curve into an event. For a positive scalar $x_t$ at step $t$, define $u_t=\log(x_t+\varepsilon)$, where $\varepsilon>0$ is a small numerical floor and $\log$ is the natural logarithm. Let $W_t$ be a window of earlier $u$-values, $q_t=\operatorname{median}(W_t)$, and

$$D_t=\operatorname{median}_{u\in W_t}|u-q_t|, \qquad z_t=0.6745\frac{|u_t-q_t|}{D_t+\varepsilon}.$$

$D_t$ is the median absolute deviation and $z_t$ is a robust deviation score. The factor 0.6745 calibrates the score for normally distributed log-values. Apply the detector separately to loss and $G_2$. When both spike on the same step, the event is usually more informative.

3. Tensor probes

Let $x=(x_1,\ldots,x_N)$ be a flattened tensor with $N$ scalar elements. The index $j$ below selects one element. One pass over memory can compute most useful summaries.

Metric Definition What it shows
Absolute mean $N^{-1}\sum_{j=1}^{N}|x_j|$ Typical scale
RMS $\sqrt{N^{-1}\sum_{j=1}^{N}x_j^2}$ Energy scale
Absolute maximum $\max_{1\le j\le N}|x_j|$ Exploding values and outliers
Zero fraction $N^{-1}\sum_{j=1}^{N}\mathbf{1}[x_j=0]$ Sparsity, underflow, or dead paths
Excess kurtosis $\frac{N^{-1}\sum_j(x_j-\mu)^4}{(N^{-1}\sum_j(x_j-\mu)^2)^2}-3$ Heavy tails

In the table, $\mathbf{1}[\mathcal{C}]$ is 1 when condition $\mathcal{C}$ is true and 0 otherwise. The symbol $\mu=N^{-1}\sum_j x_j$ is the empirical mean. RMS means root mean square. Excess kurtosis is undefined when the empirical variance is zero.

Across ranks, aggregate sums and element counts before computing means. Aggregate maxima with a maximum reduction. Do not average local maxima or ratios whose denominators differ.

Good observation points include embeddings, logits, query/key/value tensors, normalized query and key, attention output, feed-forward activations, residual streams, Mixture-of-Experts inputs, parameter gradients, and applied updates. Record forward activations and backward gradients under distinct names.

Relative update size

A useful optimizer trace follows the same parameter group through its raw gradient, normalized or preconditioned direction, and final applied update. Name each stage explicitly. Otherwise, two curves called “gradient” may describe different tensors.

Let $w$ be a parameter tensor and let $\Delta w$ be the update applied to it. With $\operatorname{RMS}(\cdot)$ defined in the table above, use

$$\rho=\frac{\operatorname{RMS}(\Delta w)} {\operatorname{RMS}(w)+\varepsilon}.$$

The dimensionless ratio $\rho$ compares update size with parameter size. A persistent fall toward zero suggests ineffective updates. A sudden rise suggests instability. The constant $\varepsilon>0$ prevents division by zero.

4. Mixture-of-Experts balance

Let $E$ be the number of experts and $c_i$ the number of tokens sent to expert $i$, where $1\le i\le E$. Define the mean count $\bar c$ and normalized load $p_i$ by

$$\bar c=\frac{1}{E}\sum_{i=1}^{E}c_i, \qquad p_i=\frac{c_i}{\sum_{j=1}^{E}c_j}.$$

In the denominator, $j$ is a dummy index over all experts. Three compact summaries are

$$I=\frac{\max_i c_i}{\bar c}, \qquad V=I-1, \qquad H=-\sum_{i=1}^{E}p_i\log p_i, \qquad H_{\mathrm{norm}}=\frac{H}{\log E}.$$

$I$ is the imbalance ratio, $V$ is excess load above the mean, $H$ is routing entropy, and $H_{\mathrm{norm}}$ is entropy normalized to the interval from 0 to 1. Perfect balance gives $I=1$, $V=0$, and $H_{\mathrm{norm}}=1$. Skip these ratios when no valid token reaches the layer.

Measure the same imbalance across expert-parallel shards. Expert counts can look balanced globally while one communication group remains overloaded. Keep $I$ and its shard-level counterpart on the main dashboard; open per-expert curves only when either one moves.

5. Residual paths

Let $s\in\mathbb{R}^{d}$ be a residual-stream vector and $b\in\mathbb{R}^{d}$ the branch output added to it. Here, $\mathbb{R}^{d}$ is the set of $d$-dimensional real vectors, and $d$ is the hidden dimension. Define

$$a=s+b, \qquad R_b=\frac{\lVert b\rVert_2}{\lVert s\rVert_2+\varepsilon}, \qquad B=1-\cos(s,a), \qquad A=\frac{\arccos(\cos(s,a))}{\pi}.$$

Here, $a$ is the updated stream, $R_b$ is relative branch scale, $B$ is block importance, and $A$ is normalized angular distance. For vectors $u$ and $v$, $\cos(u,v)=u^\top v/(\lVert u\rVert_2\lVert v\rVert_2+\varepsilon)$. The product $u^\top v$ is their dot product, $\lVert\cdot\rVert_2$ is the Euclidean norm, and $\pi$ is the circle constant.

These metrics show whether a block meaningfully changes the stream. A useful companion is the fraction of elements changed by a 32-bit floating-point addition but unchanged after bfloat16 rounding. A large fraction means small residual updates are being lost to precision.

6. System health

Model signals and system signals belong on the same timeline. At minimum, record:

  • step time and tokens per second;
  • estimated floating-point operations per second per device;
  • allocated, reserved, and peak device memory, including the maximum across ranks;
  • device utilization, power, temperature, and clock;
  • process memory, CPU pressure, and page faults;
  • network traffic, collective call count, payload size, lifetime, and exposed wait time.

For rank $r$, let $\tau_r$ be its local step time and let $\tau=\max_r\tau_r$ be the global wall time for the step. Let $N_{\mathrm{tok}}$ be the global number of valid tokens processed, $F_{\mathrm{step}}$ the estimated floating-point operations, and $D$ the number of accelerator devices. Define

$$\operatorname{TPS}=\frac{N_{\mathrm{tok}}}{\tau}, \qquad \Phi=\frac{F_{\mathrm{step}}}{D\tau}.$$

$\operatorname{TPS}$ is global tokens per second. $\Phi$ is estimated floating-point operations per second per device. A simple straggler score is

$$S=\frac{\tau}{\operatorname{median}_r(\tau_r)+\varepsilon}.$$

$S$ is the largest rank time divided by the median over ranks. It is close to 1 when workers progress together and rises when a slow rank sets the pace.

Allocated memory is memory held by live tensors. Reserved memory is the allocator pool, including unused cached blocks. Peak memory is the maximum observed value. Memory headroom should use the maximum across ranks.

Do not synchronize to measure synchronization. Place device events around the real asynchronous wait and read them at an existing boundary. A new host synchronization can erase the overlap being measured.

Node-level network counters should be sampled once per node. Reading the same interface from every local rank multiplies the reported traffic.

7. Evaluation

Training probes answer whether optimization is healthy. Evaluation asks whether capability is improving.

For $M$ valid held-out tokens with negative log-likelihoods $\ell_1,\ldots,\ell_M$, define

$$\operatorname{NLL}=\frac{1}{M}\sum_{k=1}^{M}\ell_k, \qquad \operatorname{PPL}=\exp(\operatorname{NLL}).$$

$\operatorname{NLL}$ is mean negative log-likelihood, $\operatorname{PPL}$ is perplexity, $k$ indexes held-out tokens, and $\exp$ is the natural exponential. Keep dataset, tokenizer, prompt, decoding, and post-processing versions fixed.

Evaluation Method Metric
Language modeling Score held-out text without sampling Negative log-likelihood, perplexity, bits per byte
Multiple choice Select the option with lowest length-normalized negative log-likelihood Accuracy
Deterministic generation Generate once with temperature zero Exact match, pass@1
Sampled generation Generate several independent samples Majority accuracy, pass@k
Multimodal ablation Compare the same prompt with and without media Information gain
Grounding Compare a predicted region with a reference region Intersection over union

In pass@1, one generation is evaluated. In pass@k, $k$ is the number of sampled attempts and success means at least one passes. Let $N_{\mathrm{byte}}$ be the number of source bytes covered by the held-out tokens. Bits per byte is

$$\operatorname{BPB}=\frac{\sum_{k=1}^{M}\ell_k} {N_{\mathrm{byte}}\log 2}.$$

For a media ablation, let $Q_{\mathrm{with}}$ and $Q_{\mathrm{without}}$ be the same higher-is-better quality score with and without media. Define media gain as $\Delta_Q=Q_{\mathrm{with}}-Q_{\mathrm{without}}$.

For grounding, let $\mathcal{P}$ be the predicted region and $\mathcal{G}$ the reference region. If $|\mathcal{A}|$ denotes the area of region $\mathcal{A}$, while $\cap$ and $\cup$ denote intersection and union, then

$$\operatorname{IoU}= \frac{|\mathcal{P}\cap\mathcal{G}|} {|\mathcal{P}\cup\mathcal{G}|}.$$

8. Keep probes inexpensive

  1. Register once. Choose tensor locations while building the model.
  2. Gate early. On an unsampled step, skip the tensor scan itself.
  3. Scan once. Compute several local statistics in one memory pass.
  4. Reduce in batches. Group values by distributed reduction type.
  5. Move only summaries. Keep full tensors on the device.
  6. Write asynchronously. Do not place storage latency on the training path.

Let $K$ be the regular sampling interval in steps. Retain every $K$-th sample, every anomaly step, the warm-up and final steps, and a window around each anomaly. Small runs can use $K=1$. Long runs often use $K$ between 100 and 200 for expensive views. Cheap anomaly detectors should still run every step.

A detector cannot recover expensive measurements from before an event. If that context matters, keep a short in-memory ring buffer or replay the affected batch under denser probes.

Common mistakes

  • Wrong reduction group: data, tensor, pipeline, context, and expert parallel groups have different semantics.
  • Unclear maximum: say whether a maximum is over tensor elements, tokens, examples, or distributed ranks.
  • Ambiguous timing: state whether gradients are scaled, accumulated, clipped, or already updated.
  • Duplicate recomputation: activation checkpointing may execute a forward probe again.
  • Empty shards: absence of data is not a measured zero.
  • Padding: exclude it from token and routing statistics when appropriate.
  • Over-smoothing: keep a faint raw curve behind a smoothed curve so short spikes remain visible.
  • High-cardinality labels: arbitrary parameter names and sample identifiers overwhelm online metric stores.
  • Sensitive artifacts: keep raw samples and token-level traces opt-in, access-controlled, and short-lived.

9. A small dashboard

  1. Run health. Mean and worst-rank loss, $G_2$, spike events, throughput, peak memory, and job state.
  2. Data health. Loss and token share by stable source or modality.
  3. Mixture-of-Experts health. Imbalance ratio $I$, excess load $V$, and normalized routing entropy $H_{\mathrm{norm}}$.
  4. Numerics. RMS, absolute maximum, zero fraction, and clipping state.
  5. Layer detail. Activation scale, gradient contribution, optimizer updates, and residual metrics.
  6. Model quality. Held-out negative log-likelihood and milestone evaluations against cumulative tokens or compute.

The first dashboard contains alerting signals. Higher-cost views are reserved for diagnosis.

The listed cadences are initial settings. Benchmark probe overhead on the target model, parallel configuration, and hardware before increasing frequency.
