Depth Recurrent Vectors

Teaching a pretrained Qwen3 to reuse its own middle layers, and what that does to its weights.

Chunyuan Deng · November 2026 · 17 checkpoints on Hugging Face

We took Qwen3-1.7B-Base and kept pretraining it for 20B tokens with one change: twelve of its middle layers run several times in a row, with the same weights. At three passes the test loss goes from 1.146 to 1.118, on the same data with the same recipe.

This post is the notebook behind that number: the recipe, every ablation we ran and what each one compares, and the checkpoints. The “vectors” in the title are the weight differences between a looped model and the base model. They turned out to be less portable than we hoped.

The short version

  • Looping helps. 1.1460 → 1.1178 at three passes. Each training step takes 1.84× as long as the plain model’s, and we have not yet trained a plain model that much longer.
  • How the passes are connected barely matters at the trained depth. Twenty-three variants land within 0.005 of each other. It matters a lot once you run more passes than you trained with. Only the variant where each pass re-reads the block’s original input stays stable.
  • A small loss on every pass is free in loss for that variant, and it makes the early passes usable. It does make each step 52% slower.
  • Three or four passes are equally good. Two and five are worse. If you want to pick the depth at test time, train with a random depth: it costs 0.004 at three passes, and the loss stays flat from three to eight passes.
  • Averaging the weights of independent runs gains 0.004 for free, about as much as an EMA of the weights. Together they reach 1.1125.
  • The loop does not come apart from the rest of training. Subtracting the plain run from the looped run and adding the difference to the base model sends the loss to 9.5.

Setup

All runs continue from Qwen3-1.7B-Base (28 layers, hidden size 2048):

  • Data: web text 42%, PDFs 23%, code 26%, agent trajectories 9%. That is 20.0B tokens, seen once, in 16K-token sequences packed with document masking (attention never crosses documents).
  • Optimizer: AdamW with weight decay 0.1, batches of 128 sequences (2.1M tokens), 9,551 steps, 125 warmup steps, then cosine decay to 0.1× the peak LR.
  • Evaluation: test loss on a held-out split of the same mix. Every number below is on the same test sequences.

We picked the learning rate on the plain model, then reused it for every looped run without retuning:

The loop

The 28 layers split into three parts. Layers 0–7 run once and produce $e$. The block, layers 8–19, runs $K$ times with the same weights. Layers 20–27 run once on the block’s last output $s_K$. Write $B$ for one pass through the block. Most of this post compares two ways of connecting the passes:

$$\textbf{chained:}\quad s_1 = B(e),\qquad s_r = s_{r-1} + g \odot \big(B(s_{r-1}) - s_{r-1}\big)$$
$$\textbf{anchored:}\quad s_1 = B(e),\qquad s_r = B\big(e + g \odot (s_{r-1} - e)\big)$$

$g \in \mathbb{R}^{2048}$ is one learned number per channel, shared by all passes. It trains with 5× the learning rate and no weight decay.

In both forms, $g = 0$ makes every pass compute $B(e)$, which is exactly the original Qwen3. Training therefore starts from the base model’s function, with no initial jump in loss. Chained passes refine the previous output. Anchored passes always restart from $e$ and only borrow a hint from the previous pass.

The second ingredient is optional: a loss on every pass, which we call intermediate supervision (IS). Layers 20–27 and the output head read each intermediate $s_r$ too, and those predictions join the loss with a small weight:

$$\mathcal{L} \;=\; \mathcal{L}_K \;+\; \lambda \sum_{r<K} \mathcal{L}_r,\qquad \lambda = 0.0555$$

How the passes are connected

Here $K = 3$ and the recipe stay fixed, and only the connection changes. Besides chained and anchored, we tried the following variants:

  • Data-dependent gate: $g = \sigma(\beta + f(x))$, with $f$ starting at zero. Scalar: $f = w^\top \hat{x}$, one gate per token. Low-rank: $f = W_\text{up}\,\mathrm{swish}(W_\text{down}\hat{x})$, rank 16, as in GatedNorm. The input $x$ is the previous state (state), the proposed update $B(s)-s$ (delta), or both (full). Each part is RMS-normalized.
  • Variance-preserving: $s_r = \sqrt{1-g}\odot s_{r-1} + \sqrt{g}\odot B(s_{r-1})$.
  • Injection (Parcae): the block reads $\Lambda\odot s_{r-1} + u$, where $u = \Delta\odot W\,\mathrm{norm}(e)$ and $\Lambda = e^{-\Delta\odot\alpha}\in(0,1)$. OrthoInj additionally removes the old state’s component along $u$ first.

Test loss of models trained with 3 passes and no intermediate supervision, evaluated at 1, 3, 6 and 8 passes. The plain model is 1.1460. “Gate start” is the gate’s initial value; above 0, the model starts away from the base model.

At three passes, everything lands between 1.117 and 1.122. Three runs of the same anchored setup span 0.0007, so most rows are ties. Anchored is ahead by about 0.002. Data-dependent gates did not lower the loss, and neither did a warmer start or a larger gate LR.

What separates the variants is what happens past three passes. In the chained forms, nothing pulls the state back toward where training left it, so the loss climbs with every extra pass. Data-dependent gates slow this down but do not stop it. The variance-preserving form is the worst. The anchored form stays within 0.06 out to eight passes, because every pass restarts from $e$ and the block’s input cannot run away.

The learned anchored gate is small, with a mean of 0.08–0.10 (chained gates settle at 0.22–0.43). That does not mean the loop is barely used: one pass moves the state 9–11× the size of $e$, so the hint $g\odot(s-e)$ is about as large as $e$ itself.

Without IS, one pass is useless in every variant (2.0–2.6): the model learns to rely on all three passes.

IS takes one pass from 2.0–2.5 down to about 1.2. For the anchored form it is nearly free at three passes (+0.0002 at 5× gate LR), and it flattens the zigzag beyond. For the chained forms it costs 0.003–0.004 at three passes. The real price is time: in our implementation, the extra exits make each step 52% slower (4.8 s → 7.2 s, against 2.6 s for the plain model).

From here on, every model is anchored, with gate start 0, 5× gate LR and IS.

Every model is best at exactly the depth it was trained with, and gets worse in both directions. Past that depth the pattern depends on $K$: with $K=2$ the loss rises steadily, with $K=3$ it zigzags every other pass, and with $K=4$ and $5$ it zigzags roughly every third pass.

Three and four passes are tied within seed noise. Five is worse than three on the same recipe; it may need more tokens or a different LR, and we did not tune for it.

With random depth, the loss stays flat from three to eight passes. The cost is 0.004–0.006 at three passes:

  • Weighting the draw toward 3 roughly halves that cost.
  • Switching late, for the last 20% of training only, gives the same result as sampling from the start, so flexibility can be added at the end.
  • A wider range (up to 5) is worse everywhere.
  • The chained form still drifts, even with random depth.
  • IS matters less here at three passes (0.001), but one pass still needs it.

Depth recurrent vectors

Call $v = \theta_\text{loop} - \theta_\text{base}$ the depth recurrent vector of a run. If looping lived in a direction of weight space, we could move it around: add it to another model, scale it, or average it. We wrote a small tool to do arithmetic on checkpoints and scored every result on the same test set.

A few sizes for scale, all relative to $\lVert\theta_\text{base}\rVert$:

  • $\lVert v\rVert$ is 23%, about the same as for the plain run (22.6%).
  • A looped run and its exact repeat end 15.5% apart.
  • The looped and plain runs end 17.5% apart.

EMA is a running average of the weights during training (power EMA, $\gamma = 36.7$), which mostly covers the last few percent of steps.

The loss never rises anywhere on the line between two runs. They sit in one basin, and the 15.5% distance between them is drift along flat directions. Averaging gains about as much as EMA, and the two only partly stack. Averaging a 3-pass model with a 4-pass model cancels their zigzags: the loss is 1.120–1.128 all the way out to eight passes.

“Plain” is the run without looping; “looped” is 3-pass run 1; runs 1 and 2 are the same 3-pass setup with the same seed.

The difference between the looped and plain runs is not “the ability to loop”: adding it to the base model breaks the model. The gate on its own does nothing either. The ability to loop lives in the block’s weights, trained together with everything else.

The last two rows show why this kind of transfer fails in general. Run 1 − run 2 is harmless inside the looped basin, where moving between them is flat. Added to another model, the same vector costs 0.24 nats or destroys the model outright. A weight difference is only safe near where it was made.

This matters for transfer to post-trained models. Adding $v$ to a post-trained model computes $\theta_\text{loop} + (\theta_\text{post} - \theta_\text{base})$, and whether that works depends on how far post-training moved the weights. We don’t know yet; that is what the checkpoints are for.

Each pass keeps its own KV cache, so at three passes the cache is about 1.9× that of a plain Qwen3-1.7B. On our test text, the Hugging Face port matches our Megatron training code to within a few thousandths of a nat at every depth. vLLM does not support the architecture yet.

What’s missing

  • A compute-matched control: the plain model trained 1.84× as long. Until then, “looping helps” means per parameter and per token, not per unit of compute.
  • Downstream tasks. Everything here is next-token loss.
  • Breadth. One model size, one data mix, and one learning rate, tuned for the plain model.
  • Transfer. Adding the vectors to a post-trained model has not been tested yet.
