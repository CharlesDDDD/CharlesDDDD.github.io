Probe Metrics for Large-Scale Pretraining

A calm, practical guide to what to watch, how often to sample, and what each signal means

Chunyuan Deng · September 2026

In brief. Training runs stay calm when monitoring has a simple layout. Start with six focused dashboard cards answering one immediate question: does anyone need to intervene? When a signal moves, lean on layered probe metrics to uncover why without adding heavy overhead to training.

The Core Dashboard: Six Views at a Glance

Rather than cluttering your main screen with dozens of graphs, these six cards capture the complete health of a pretraining run in seconds.

Card 01
Run Pulse

Global loss, worst-rank loss ($L_{\max}$), gradient L2 norm ($G_2$), step time, and memory headroom.

Card 02
Data Streams

Loss and token share broken down by source or modality to catch bad data shards early.

Card 03
MoE Routing

Expert imbalance ratio ($I$), excess load ($V$), and routing entropy ($H$) across parallel groups.

Card 04
Numerics

RMS, absolute maximum, and zero fractions across weights and activations to prevent drift.

Card 05
Layers & Residuals

Relative update scale ($\rho$) and residual branch contributions to ensure all layers actively learn.

Card 06
Model Quality

Held-out perplexity (PPL) and milestone benchmark scores plotted against compute (FLOPs/Tokens).

1. Sampling Cadence: A Sustainable Rhythm

The golden rule of training probes is simple: sampling cost should rise as frequency falls. Keeping lightweight alerts on every step and saving heavier tensor sweeps for regular intervals preserves training throughput.

Cadence What to collect Purpose
Every step Global and worst-rank loss, gradient norm ($G_2$), step time, throughput, peak memory Immediate alerting
Every 10–50 steps Loss by data source, allocator state, CPU/network load Short-term trends
Every 100–200 steps Layer activations, gradients, optimizer states, residual ratios, MoE routing Deep diagnosis
Periodic (0.5–2%) Lightweight held-out validation suite (PPL / NLL) Generalization progress
On anomaly Dense multi-step capture around loss spikes or gradient explosions Root cause inspection

A steady horizontal axis: Always plot curves against cumulative tokens or estimated FLOPs rather than step number alone, ensuring fair comparisons whenever batch size or sequence length adjusts.

2. Core Optimization Health

Global Loss vs. Worst-Worker Loss

A smooth average loss curve can conceal a failing worker. Tracking both the globally weighted loss $L$ and the highest worker-level mean $L_{\max}$ keeps health transparent:

$$L = \frac{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}\ell_{r,t}}{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}}, \qquad L_{\max} = \max_{1\le r\le R} L_r$$

Note: Avoid computing a simple "average of averages." Always sum numerators and token counts globally so each token receives equal weight regardless of how data is distributed across ranks.

Gradient Norm and Calm Spike Detection

The unclipped global gradient L2 norm ($G_2 = \sqrt{\sum_j g_j^2}$) provides your clearest early warning before loss spikes occur. Rather than reacting to normal step-by-step noise, a robust median absolute deviation (MAD) on log-transformed values flags genuine anomalies:

$$u_t = \log(x_t + \varepsilon), \qquad z_t = 0.6745 \frac{|u_t - \operatorname{median}(W_t)|}{\operatorname{MAD}(W_t) + \varepsilon}$$

When loss and $G_2$ produce simultaneous spikes ($z_t > 3$), it is time to inspect that window closely.

3. Layer Numerics and Residual Paths

A single pass over tensors during diagnostic steps provides key health signals without memory overhead:

  • RMS and Absolute Max: $\operatorname{RMS}(x) = \sqrt{N^{-1}\sum x_j^2}$ indicates typical energy; $\max |x_j|$ catches outliers before underflow/overflow occurs.
  • Zero Fraction: Spots dead ReLU/SwiGLU pathways or precision underflow early.
  • Relative Update Size ($\rho$): Compares update magnitude to parameter magnitude:
    $$\rho = \frac{\operatorname{RMS}(\Delta w)}{\operatorname{RMS}(w) + \varepsilon}$$
    A steady drop toward zero indicates stalled optimization; a sudden jump signals instability.
  • Residual Branch Contribution: For residual update $a = s + b$, track $R_b = \frac{\lVert b\rVert_2}{\lVert s\rVert_2}$ and cosine distance $1 - \cos(s,a)$ to ensure deeper layers contribute meaningfully without precision loss from bfloat16 rounding.

4. MoE Routing & System Harmony

In Mixture-of-Experts architectures, balance is essential. Track the expert imbalance ratio $I$ and routing entropy $H$:

$$I = \frac{\max_i c_i}{\bar c}, \qquad H = -\sum_{i=1}^{E} p_i \log p_i$$

Check routing load across individual expert-parallel communication groups as well; global loads can appear balanced even when an isolated worker is overwhelmed.

For system efficiency, monitor the worker straggler score $S = \frac{\max \tau_r}{\operatorname{median}(\tau_r)}$. Record timing events asynchronously at existing synchronization boundaries rather than forcing new host barriers that interrupt pipeline overlap.

5. Guiding Principles for Clean Probes

  1. Register once: Attach hooks during model construction, avoiding dynamic allocations inside the training loop.
  2. Gate early: On unsampled steps, skip data gathering immediately at the hook entry.
  3. Single-pass passes: Compute RMS, max, and zeros in one fused kernel.
  4. Transfer only scalars: Keep tensor data on-device; send only reduced summary scalars to storage.
  5. Write asynchronously: Logging should never sit directly on the critical execution path.
This guide provides an engineering baseline for distributed pretraining. Always measure probe overhead on your specific hardware topology to maintain an unobtrusive observer.
