Training observability

Reading a Pretraining Run

What to watch, what to ignore, and how to define each metric so that two runs stay comparable.

Chunyuan Deng · September 2026

Contents
1. The first screen 2. Metric index 3. Loss 4. Gradients and spikes 5. System health 6. Tensor probes 7. Expert balance 8. Residual paths 9. Modality paths 10. Evaluation 11. Keeping probes cheap

A probe is a measurement attached to a training run. A large run emits tens of thousands of them. The hard part is not collecting more; it is knowing which ten belong in front of a person at three in the morning, which fifty to open once one of those ten moves, and which thousands exist only for a specific investigation.

So every metric here carries a priority as well as a definition, an aggregation rule, and a default cadence.

P0

Alert. Cheap enough to compute every step and wired to a pager. Roughly ten metrics. If one of them moves, the run stops or someone wakes up.

P1

Diagnose. Read when a P0 moves. Usually per-layer or per-tensor, sampled every hundred steps or so. Nobody watches these continuously.

P2

Forensics. Per-parameter, per-expert, per-domain detail. Opened for one investigation or one design decision, then closed.

Most of what a training stack emits is P2, and that is fine — as long as nobody is asked to watch it. The failure mode is the opposite one: a dashboard where every panel looks equally urgent, so none of them is.

Part I · Where to look

01 The first screen

If you build one page, build this one. Nine signals, all P0, all computed every step except the last.

Loss
Global and worst-rank mean

Convergence, plus whether one worker or one data shard is carrying all the damage.

Loss
By source and modality

A domain or a modality regressing while the global curve stays flat.

Gradients
Global norm and clip rate

The earliest numerical warning. It usually moves before the loss does.

Stability
Co-spike count

Loss and gradient norm spiking on the same step — the highest-confidence instability event.

System
Step time and throughput

Stalls, replays, stragglers, and communication regressions, in one curve.

System
Peak memory, max over ranks

How much headroom is left before the first device runs out of memory.

Experts
Imbalance ratio

Routing collapse, and the compute imbalance it creates across the job.

Numerics
Absolute maximum at the output

Overflow and silent corruption, a few steps before they reach the loss.

Quality
Held-out loss per byte

Whether the run is still buying quality with compute. Evaluated every 0.5–2%.

Three screens sit behind it, opened only when the first one moves.

Data

Loss and token share by source and modality, document length, packing statistics.

Numerics

Tensor scales and maxima, update ratios, residual and gate statistics, per-layer gradient contribution.

Quality

Held-out loss and milestone evaluations, plotted against cumulative tokens or compute — never against steps.

Escalation order. When the first screen moves, this sequence resolves most incidents fastest: job state, then loss, then gradient norm and spikes, then step time, then memory, then expert balance. Open the layer-level views only after that ordering has failed to explain the symptom.

Cadence rule. Cheap alerting metrics run every step. Tensor scans run every hundred steps. Evaluation runs every 0.5–2% of training. An anomaly triggers denser probes or a replay. These are starting points, not constants — benchmark them on the target model before tightening any of them.

Comparison axis. If batch size changes, compare runs by cumulative tokens or estimated floating-point operations, never by step.

Part II · Every step

03 Loss

Let $R$ be the number of GPU ranks — one training process each. Rank $r$ contains $T_r$ token positions. For token $t$ on rank $r$, $\ell_{r,t}$ is its negative log-likelihood and $m_{r,t}$ is 1 for a valid target and 0 otherwise.

Global mean loss $L$.P0 Sum valid-token loss and valid-token count over all ranks, then divide.

$$L = \frac{\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}\ell_{r,t}} {\sum_{r=1}^{R}\sum_{t=1}^{T_r} m_{r,t}}.$$

Use $L$ for convergence and scaling comparisons.

Local mean loss $L_r$.P1 Compute the valid-token mean on rank $r$.

$$L_r = \frac{\sum_{t=1}^{T_r}m_{r,t}\ell_{r,t}} {\sum_{t=1}^{T_r}m_{r,t}}.$$

Omit a rank with no valid target; do not record it as zero.

Worst-rank loss $L_{\max}$.P0 Take the maximum local mean over ranks.

$$L_{\max}=\max_{1\le r\le R}L_r.$$

Use $L_{\max}$ to detect a bad worker or an unusual data shard hidden by $L$. It is a maximum over GPU ranks, not over tokens or examples.

Loss by source and modality.P0 Let $\mu$ index a stable data source or modality, and let $m^{(\mu)}_{r,t}$ be 1 when token $t$ on rank $r$ is a valid target belonging to $\mu$. Report the group loss together with its token share.

$$L^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}\ell_{r,t}} {\sum_{r,t} m^{(\mu)}_{r,t}}, \qquad \pi^{(\mu)}=\frac{\sum_{r,t} m^{(\mu)}_{r,t}} {\sum_{r,t} m_{r,t}}.$$

A group holding a few percent of the tokens can regress for thousands of steps without moving $L$. That is the single most common way a real problem stays invisible, which is why this belongs on the first screen rather than in a drill-down. Compare each group against its own history: absolute loss levels are not comparable across sources, because their token entropies differ.

Aggregation: do not average $L_r$ when valid-token counts differ. Reduce the loss sum and the token count separately, then divide.

04 Gradients and spikes

Let $g=(g_1,\ldots,g_P)$ contain all $P$ gradient elements. The index $j$ selects one element. Measure after gradient accumulation and loss-scale removal, but before global clipping.

Global gradient norm $G_2$.P0 Compute the Euclidean norm over all gradient elements.

$$G_2=\sqrt{\sum_{j=1}^{P}g_j^2}.$$

This is the primary numerical-stability signal, and usually the first thing to move in a failing run.

Clip rate.P0 With clip threshold $c$ and a window of $W$ recent steps, report the fraction of steps that were clipped.

$$\operatorname{Clip}=\frac{1}{W}\sum_{t}\mathbf{1}[G_{2,t}>c].$$

A low steady rate is normal. A sustained rise means the threshold no longer matches the run's gradient scale, and clipping has quietly become a learning-rate schedule you did not design.

Mean absolute gradient $G_{\mathrm{mean}}$.P1 Average the absolute gradient elements.

$$G_{\mathrm{mean}}=\frac{1}{P}\sum_{j=1}^{P}|g_j|.$$

This tracks typical element scale and is less sensitive to one outlier than $G_{\max}$.

Maximum absolute gradient $G_{\max}$.P1 Take the largest absolute gradient element.

$$G_{\max}=\max_{1\le j\le P}|g_j|.$$

This detects localized explosion that $G_{\mathrm{mean}}$ dilutes away.

Gradient zero fraction $Z_g$.P1 Count exact zeros and divide by the number of gradient elements.

$$Z_g=\frac{1}{P}\sum_{j=1}^{P}\mathbf{1}[g_j=0].$$

The indicator $\mathbf{1}[\mathcal{C}]$ equals 1 when condition $\mathcal{C}$ is true and 0 otherwise. A rise in $Z_g$ indicates sparse paths, underflow, or parameters receiving no gradient at all. Report it separately for embeddings and for expert parameters, where sparsity is expected and a change in it still matters.

Timing: record whether each gradient metric is scaled or unscaled, accumulated or per-microbatch, and before or after clipping. Two runs whose gradient norms are measured at different points in the optimizer are not comparable.

Spike detection

For a positive scalar $x_t$ at step $t$, define $u_t=\log(x_t+\varepsilon)$, where $\varepsilon>0$ is a numerical floor and $\log$ is the natural logarithm. Let $W_t$ contain earlier $u$-values.

Rolling median $q_t$.P1 Use the median of the log-space window as the local baseline.

$$q_t=\operatorname{median}(W_t).$$

The median is robust to isolated spikes.

Median absolute deviation $D_t$.P1 Measure the median distance from the rolling median.

$$D_t=\operatorname{median}_{u\in W_t}|u-q_t|.$$

$D_t$ estimates recent variability without using a variance that a spike can inflate.

Robust spike score $z_t$.P1 Normalize the current deviation by $D_t$.

$$z_t=0.6745\frac{|u_t-q_t|}{D_t+\varepsilon}.$$

The factor 0.6745 calibrates the score for normally distributed log-values. Apply the detector separately to $L$ and $G_2$.

Co-spike indicator $C_t$.P0 Mark a step only when loss and gradient norm both spike.

$$C_t=\mathbf{1}[\text{loss spike at step }t]\, \mathbf{1}[\text{gradient-norm spike at step }t].$$

$C_t=1$ is a far higher-confidence instability event than either detector alone, and it is the one worth paging on. Track the cumulative count and the cumulative magnitude, not just the instantaneous flag.

Skip and replay counters.P1 Some runs discard the optimizer update on a detected spike and re-run the step. Count skipped updates, replayed steps, and replays that did not reproduce the original loss.

The last counter is the valuable one: a replay that returns a different loss on identical inputs points at hardware, not at data.

Thresholds: calibrate the window length and the $z_t$ threshold on stable runs. Do not tune them on a single failure.

05 System health

Let $\tau_r$ be the local step time on rank $r$, and let $\tau=\max_r\tau_r$ be the global wall time of the step.

Token throughput $\operatorname{TPS}$.P0 Let $N_{\mathrm{tok}}$ be the global number of valid tokens processed in one step.

$$\operatorname{TPS}=\frac{N_{\mathrm{tok}}}{\tau}.$$

This is the end-to-end training rate. Include data loading, forward, backward, optimizer, and synchronization in $\tau$.

Compute rate $\Phi$.P0 Let $F_{\mathrm{step}}$ be estimated floating-point operations per step and $D$ the number of accelerator devices.

$$\Phi=\frac{F_{\mathrm{step}}}{D\tau}.$$

$\Phi$ is estimated operations per second per device. Keep the FLOP estimator fixed across compared runs; changing the estimator changes the metric without changing the hardware.

Straggler score $S$.P1 Divide the global step time by the median local step time.

$$S=\frac{\tau}{\operatorname{median}_r(\tau_r)+\varepsilon}.$$

$S$ is close to 1 when ranks progress together. It rises when one slow rank sets the step time for everyone.

Peak memory.P0 Maximum allocated or reserved bytes observed during the measurement interval, reduced with a maximum over ranks.

The maximum over ranks is the number that matters: it identifies the device closest to an out-of-memory failure. Reset peak counters only at documented boundaries; otherwise adjacent points describe different windows.

Allocated and reserved memory.P1 Allocated bytes are held by live tensors; reserved bytes are held by the device allocator, including cached blocks.

A widening reserved-minus-allocated gap indicates fragmentation or an oversized allocator cache, not a larger model.

Exposed collective wait $W_{\mathrm{comm}}$.P1 Let $\tau_{\mathrm{wait}}$ be collective time on the critical path that is not overlapped with useful computation.

$$W_{\mathrm{comm}}=\frac{\tau_{\mathrm{wait}}}{\tau}.$$

Report collective count and payload alongside $W_{\mathrm{comm}}$, to separate many small calls from one bandwidth-limited large call.

Device and host telemetry.P1 Record device utilization, power, temperature, clock, process memory, CPU pressure, page faults, and network traffic.

These signals separate model regressions from host, thermal, allocator, and network failures — which is most of what a throughput drop turns out to be.

Timing: place device events around the real asynchronous wait and read them at an existing synchronization boundary. Adding host synchronization changes the overlap you are trying to measure.

Node counters: sample each network interface once per node. Reading it from every local rank multiplies the reported traffic by the number of ranks.

Part III · Every hundred steps

06 Tensor probes

Let $x=(x_1,\ldots,x_N)$ be a flattened tensor with $N$ scalar elements. The index $j$ selects one element. One pass over memory can produce all of the statistics below at once.

Absolute maximum.P0 Take the largest absolute element.

$$\operatorname{AbsMax}(x)=\max_{1\le j\le N}|x_j|.$$

This is the fastest indicator of an outlier, an overflow, or a local numerical explosion. At the model output it is a P0 signal in its own right: it moves before the loss does.

Root mean square.P1 Take the square root of the mean squared element value.

$$\operatorname{RMS}(x)=\sqrt{\frac{1}{N}\sum_{j=1}^{N}x_j^2}.$$

RMS measures energy scale and stays comparable across tensors with different element counts. Store the square mean $M_2(x)=\frac1N\sum_j x_j^2$ rather than RMS itself: ranks can reduce the squared sum and the element count separately, and RMS follows.

Absolute mean.P1 Average the absolute element values.

$$\operatorname{AbsMean}(x)=\frac{1}{N}\sum_{j=1}^{N}|x_j|.$$

This measures typical scale without sign cancellation. Compared with RMS it is insensitive to a few large elements, so the gap between the two is itself informative.

Zero fraction $Z_x$.P1 Count exact zeros and divide by $N$.

$$Z_x=\frac{1}{N}\sum_{j=1}^{N}\mathbf{1}[x_j=0].$$

$Z_x$ measures sparsity, underflow, and inactive paths.

Excess kurtosis $\kappa$.P2 Let $\mu=\frac{1}{N}\sum_{j=1}^{N}x_j$ be the empirical mean. Normalize the fourth central moment by the squared variance.

$$\kappa= \frac{\frac{1}{N}\sum_{j=1}^{N}(x_j-\mu)^4} {\left(\frac{1}{N}\sum_{j=1}^{N}(x_j-\mu)^2\right)^2}-3.$$

Large positive $\kappa$ indicates heavy tails, which is a low-precision risk. The metric is undefined when the empirical variance is zero. Weights are worth tracking here; activations usually are not.

Observation points. Embeddings, logits, query/key/value tensors, normalized query and key, attention output, feed-forward activations, residual streams, expert inputs and outputs, parameter gradients, and applied updates. Use distinct names for forward activations and backward gradients — the pair is what makes the scan diagnostic.

Reading an explosion. Walk the absolute maximum of the backward pass from the output inward: model output, then each block's pre-clip tensors, then attention and feed-forward internals. The first layer that jumps is the layer to investigate.

Distributed reduction: aggregate sums and element counts before computing means. Aggregate maxima with a maximum reduction. Never average local maxima, or ratios whose denominators differ.

Relative update size

Relative update size $\rho$.P1 Let $w$ be a parameter tensor and $\Delta w$ the update applied to it.

$$\rho=\frac{\operatorname{RMS}(\Delta w)} {\operatorname{RMS}(w)+\varepsilon}.$$

A persistent fall toward zero indicates ineffective updates. A sudden rise indicates an update large relative to the parameter scale. This ratio is comparable across layers and across runs; the raw update norm is not.

Optimizer chain.P2 For the same parameter group, record the raw gradient, the normalized gradient, the preconditioned direction, and the final applied update as separate tensors.

This locates the stage that introduces a scale or direction change. It is a lot of series for a lot of parameters, so keep it out of the standing dashboard and turn it on for an investigation.

Naming: specify whether an optimizer tensor is before or after normalization, preconditioning, weight decay, learning-rate scaling, and clipping.

07 Expert balance

Let $E$ be the number of experts and $c_i$ the number of valid tokens sent to expert $i$, where $1\le i\le E$.

Imbalance ratio $I$.P0 Compare the busiest expert with the mean load $\bar c=\frac1E\sum_i c_i$.

$$I=\frac{\max_{1\le i\le E}c_i}{\bar c}.$$

Perfect balance gives $I=1$. Larger values identify routing collapse and the compute imbalance that follows it.

Excess load $V$.P0 Subtract the balanced baseline from $I$.

$$V=I-1.$$

Perfect balance gives $V=0$. A value of 0.25 means the busiest expert receives 25% more tokens than the mean. $V$ is the more readable of the two on a dashboard, because it is zero when nothing is wrong.

Shard imbalance.P0 Apply the definition of $I$ to expert-parallel shard loads rather than to individual experts.

Expert-level balance does not guarantee balanced communication groups, and it is the shard load, not the expert load, that sets the step time.

Normalized expert load $p_i$.P1 Divide expert $i$'s token count by the total routed-token count.

$$p_i=\frac{c_i}{\sum_{j=1}^{E}c_j}.$$

The symbol $j$ is a dummy index over all experts, and $\sum_i p_i=1$.

Routing entropy $H$ and its normalized form.P1 Compute Shannon entropy from the normalized loads and divide by its maximum for $E$ experts.

$$H=-\sum_{i=1}^{E}p_i\log p_i, \qquad H_{\mathrm{norm}}=\frac{H}{\log E}.$$

$H_{\mathrm{norm}}=0$ means complete concentration; $H_{\mathrm{norm}}=1$ means uniform routing. A sharp drop means the router is collapsing onto a few experts, usually before $I$ makes it obvious.

Per-expert load and router scores.P2 Per-expert token fractions, routing bias terms, and the distribution of top-$k$ margins.

These answer which expert and by how much, once the aggregate has already told you that something is wrong.

Masking: exclude padding and invalid tokens. Skip ratios entirely when no valid token reaches the layer — an empty shard is not a measured zero.

08 Residual paths

Let $s\in\mathbb{R}^{d}$ be one token's residual-stream vector and $b\in\mathbb{R}^{d}$ the branch output added to it, where $d$ is the hidden dimension. Let $a=s+b$ be the updated stream.

Relative branch scale $R_b$.P0 Divide the branch norm $N_b=\lVert b\rVert_2$ by the stream norm $N_s=\lVert s\rVert_2$.

$$R_b=\frac{N_b}{N_s+\varepsilon}.$$

A small $R_b$ indicates a branch too weak to matter; a large one indicates a branch that overwrites the stream. Plotted across depth it is the clearest single view of whether a deep model is actually using its depth. Report $N_s$ and $N_b$ separately as well — the ratio alone cannot distinguish a shrinking branch from a growing stream.

For vectors $u$ and $v$, define cosine similarity as

$$\cos(u,v)= \frac{u^\top v}{\lVert u\rVert_2\lVert v\rVert_2+\varepsilon}.$$

The product $u^\top v$ is the dot product, $\lVert\cdot\rVert_2$ is the Euclidean norm, and $\varepsilon>0$ prevents division by zero.

Block importance $B$ and angular distance $A$.P1 Measure the directional change from $s$ to $a$, raw and normalized.

$$B=1-\cos(s,a), \qquad A=\frac{\arccos(\cos(s,a))}{\pi}.$$

$B=0$ when the update preserves direction, and $A$ lies between 0 and 1. A block whose $B$ decays toward zero has stopped contributing, whatever its branch norm says.

BF16 no-op fraction $F_{\mathrm{noop}}$.P1 Let $Q_{\mathrm{BF16}}(\cdot)$ round a real value to bfloat16. For feature index $j$, count a nonzero branch update that rounded addition throws away.

$$F_{\mathrm{noop}}= \frac{1}{d}\sum_{j=1}^{d} \mathbf{1}\!\left[ Q_{\mathrm{BF16}}(s_j+b_j)=Q_{\mathrm{BF16}}(s_j) \ \land\ b_j\ne0 \right].$$

A large value means residual updates are being swallowed by precision. This grows naturally as the stream norm grows, so watch it together with $N_s$.

Gate saturation fraction.P1 For architectures that scale a branch by a learned gate, let $\beta_j=\sigma(g_j/T)$ with logistic $\sigma$, gate parameter $g_j$, and temperature $T$. Report the fraction of channels below a small threshold $\theta$.

$$F_{\mathrm{gate}}(\theta)=\frac{1}{d}\sum_{j=1}^{d}\mathbf{1}[\beta_j<\theta].$$

Track a few thresholds, for example $\theta\in\{0.05,0.1,0.25\}$. A branch whose gates have all closed contributes nothing and will not usually reopen on its own.

Aggregation: compute these per valid token, then report the mean and the upper quantiles. Flattening all tokens and features together hides exactly the token-level outliers you are looking for.

09 Modality paths

A multimodal run has all of the failure modes above, plus a class of its own: one modality degrading, or never contributing in the first place, while the aggregate curves look healthy. Three probes cover most of it. The fourth check — whether media inputs carry information at all — belongs to evaluation, and appears in the next section.

Token share $\pi^{(\mu)}$.P0 The fraction of valid target tokens belonging to modality $\mu$, defined in Section 3 alongside $L^{(\mu)}$.

Plot it next to the per-modality loss. A data-mix change, a packing bug, or a decoder that silently dropped a shard shows up here first, and it explains loss movements that otherwise look like model regressions.

Projected media scale ratio $\gamma$.P0 Let $e^{(\mathrm{media})}$ be the embeddings that an encoder and its projector hand to the language backbone, and $e^{(\mathrm{text})}$ the text-token embeddings entering at the same point.

$$\gamma=\frac{\operatorname{RMS}(e^{(\mathrm{media})})} {\operatorname{RMS}(e^{(\mathrm{text})})+\varepsilon}.$$

Values near 1 mean the two streams enter at the same scale. A persistently small $\gamma$ means the backbone can ignore media tokens at no cost to the loss, and it will. A large $\gamma$ means media tokens dominate the early layers, and the encoder's gradients set the pace for the whole model. Both are projector problems far more often than encoder problems.

Encoder gradient share $S_{\mathrm{enc}}$.P1 Divide the squared gradient norm of the encoder parameters by the squared global gradient norm.

$$S_{\mathrm{enc}}= \frac{\lVert g_{\mathrm{enc}}\rVert_2^{2}} {\lVert g\rVert_2^{2}}.$$

Compare it against the encoder's share of parameters. A share collapsing toward zero means the encoder has effectively frozen itself; a share far above its parameter share early in training points at the same projector scale problem that $\gamma$ measures. The same decomposition applies per layer and per module, which is how a gradient-contribution view is built.

Variable media length: samples carry different numbers of tiles or frames, so weight per-modality statistics by token count rather than averaging over samples. A rank that received no media in a step has no measurement, not a zero.

Scale honestly: a modality with a small token share produces a noisy loss curve. Publish $\pi^{(\mu)}$ next to $L^{(\mu)}$ so a reader can tell a real regression from a thin sample.

Part IV · Every checkpoint

10 Evaluation

Let $M$ be the number of valid held-out tokens, $\ell_k$ the negative log-likelihood of token $k$, and $k\in\{1,\ldots,M\}$ the token index.

Mean negative log-likelihood and perplexity.P0 Average held-out token losses, and exponentiate.

$$\operatorname{NLL}=\frac{1}{M}\sum_{k=1}^{M}\ell_k, \qquad \operatorname{PPL}=\exp(\operatorname{NLL}).$$

Lower is better. Perplexity adds no information over NLL; it is comparable only when tokenization and loss normalization are held fixed.

Bits per byte.P0 Let $N_{\mathrm{byte}}$ be the number of source bytes covered by the held-out tokens.

$$\operatorname{BPB}=\frac{\sum_{k=1}^{M}\ell_k} {N_{\mathrm{byte}}\log 2}.$$

BPB is the right default for comparing runs, because it is insensitive to tokenizer vocabulary and segmentation in a way token-level perplexity is not.

Choice accuracy.P0 Let $Q$ be the number of questions, $\hat a_q$ the prediction for question $q$, and $a_q$ its reference answer.

$$\operatorname{Accuracy}= \frac{1}{Q}\sum_{q=1}^{Q}\mathbf{1}[\hat a_q=a_q].$$

For multiple choice, select $\hat a_q$ by length-normalized option NLL. Keep prompt construction and answer normalization frozen for the life of the run.

Greedy generation.P0 Decode at temperature 0 and score after task-specific post-processing: exact match, pass@1, or a symbolic checker.

This is the cheapest evaluation that exposes failures likelihood-based scoring cannot see, and it is worth running on every key checkpoint rather than only at the end.

Media gain $\Delta_{\mathrm{media}}$.P0 Let $Q_{\mathrm{with}}$ and $Q_{\mathrm{without}}$ be the same higher-is-better score computed with and without the media input.

$$\Delta_{\mathrm{media}}= Q_{\mathrm{with}}-Q_{\mathrm{without}}.$$

This is the only metric that proves a multimodal model is using its media input rather than answering from text priors. A capable model with $\Delta_{\mathrm{media}}\approx 0$ is a unimodal model with extra cost.

Pass at $k$.P1 For one problem, let $n$ be the number of generated samples, $c$ the number that pass, and $k\le n$ the evaluation sample count.

$$\widehat{\operatorname{pass@}k} =1-\frac{\binom{n-c}{k}}{\binom{n}{k}}.$$

The binomial coefficient $\binom{a}{b}$ counts size-$b$ subsets of $a$ items. If $n-c<k$, the estimate is 1. Pass@1 evaluates one attempt; larger $k$ measures coverage under repeated sampling.

Intersection over union.P1 Let $\mathcal{P}$ be a predicted region and $\mathcal{G}$ its reference region, with $|\mathcal{A}|$ the area of region $\mathcal{A}$.

$$\operatorname{IoU}= \frac{|\mathcal{P}\cap\mathcal{G}|} {|\mathcal{P}\cup\mathcal{G}|}.$$

IoU is 0 for no overlap and 1 for identical regions. Promote it to P0 for a run whose target capabilities are grounding-heavy.

Averaged-weight evaluation.P1 Evaluate a running average of the weights alongside the raw ones.

Mid-run comparisons on raw weights are noisy enough to reverse a ranking between two recipes. Decide once which weight stream is the reference for decisions, and report it consistently.

Comparability: version the dataset, tokenizer, prompt, decoding parameters, post-processing, and judge. A metric change is uninterpretable if its definition also changed.

Extrapolation: when a scaling fit is used to predict a larger run, report a bound outside the fitted range rather than a point estimate. The fit is evidence about the region it covers.

Part V · Practice

11 Keeping probes cheap

  1. Register once. Choose tensor locations while building the model.
  2. Gate early. On an unsampled step, skip the scan itself, not just the write.
  3. Scan once. Compute every local statistic for a tensor in one pass over memory.
  4. Reduce in batches. Group values by reduction type and issue one collective per group.
  5. Move only summaries. Keep full tensors on the device.
  6. Write asynchronously. Never put storage latency on the training path.

Let $K$ be the regular sampling interval in steps. Retain every $K$-th sample, every anomaly step, the warm-up and final steps, and a window on both sides of each anomaly. Small runs can use $K=1$. Long runs typically use $K$ between 100 and 200 for expensive views, while cheap detectors keep running every step. A reasonable default for retention around an event is 50 to 100 steps on each side.

A detector cannot recover expensive measurements from before the event that triggered it. If that context matters, keep a short in-memory ring buffer, or replay the affected batch under denser probes.

Common mistakes

  • Everything is P0: if every panel can page you, none of them does. The priority ladder is only useful if most metrics sit below the top of it.
  • Wrong reduction group: data, tensor, pipeline, context, and expert-parallel groups have different semantics.
  • Unclear maximum: say whether a maximum is over tensor elements, tokens, examples, or GPU ranks.
  • Ambiguous timing: state whether gradients are scaled, accumulated, clipped, or already applied.
  • Duplicate recomputation: activation checkpointing may run a forward probe a second time.
  • Empty shards: absence of data is not a measured zero.
  • Padding: exclude it from token, routing, and modality statistics.
  • Over-smoothing: keep a faint raw curve behind the smoothed one, so short spikes stay visible.
  • High-cardinality labels: arbitrary parameter names and sample identifiers overwhelm online metric stores.
  • Sensitive artifacts: keep raw samples and token-level traces opt-in, access-controlled, and short-lived.

The cadences here are initial settings, and the priorities are defaults for a general run — a grounding-heavy or a stability-critical run will move a few metrics up a level. Benchmark probe overhead on the target model, parallel configuration, and hardware before increasing any frequency.
